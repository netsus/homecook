## R2-S5-001 — 신청 실패 뒤 입력을 수정하면 재시도가 멈춤

[round2-client.ts:309](https://github.com/netsus/homecook/blob/783ae392c648ed43d481e2166c6f42f0cc0a7912/lib/marketing/round2-client.ts#L309)은 이메일이나 동의가 바뀌면 `leadAttempt`를 지우지만 기존 오류를 남긴다. [retry():314](https://github.com/netsus/homecook/blob/783ae392c648ed43d481e2166c6f42f0cc0a7912/lib/marketing/round2-client.ts#L314)는 남은 요청이 없고 연결이 ready이면 빈 대기열만 처리하고 true를 반환한다. [round2-view.tsx:318](https://github.com/netsus/homecook/blob/783ae392c648ed43d481e2166c6f42f0cc0a7912/components/marketing/round2/round2-view.tsx#L318)은 오류가 있는 동안 원래 신청 버튼을 숨긴다.

재현 순서:

1. 연결된 참여에서 알림 신청을 제출하고 503 또는 네트워크 오류를 받는다.
2. 이메일을 고치거나 동의를 해제했다가 다시 선택한다.
3. 보안 확인을 새로 받은 뒤 현재 폼의 ‘다시 시도’를 누른다.
4. 추가 요청 없이 기존 오류가 남아 진행되지 않는다.

| 가짜 응답 조건 | 입력 변경 | 재시도 2회 반환 | 추가 POST | 최종 상태 |
| --- | --- | --- | --- | --- |
| 503 LEAD_CAPTURE_UNAVAILABLE | 이메일 | true / true | 0 | 오류 유지, lead started |
| 같은 503 | 동의 off/on | true / true | 0 | 동일 |
| NETWORK_ERROR | 이메일 | true / true | 0 | 동일 |
| 같은 네트워크 오류 | 동의 off/on | true / true | 0 | 동일 |
| 각 오류의 대조군 | 변경 없음 | false / false | 각4 | 같은 event로 전송을 재시도 |

대조군의 추가4 POST는 cookie bootstrap2와 lead2다. 실패 응답을 계속 주었기 때문에 false이며, 재시도 자체가 수행됐다는 비교 근거다. 새 재현은 recording에서 수행했으며 homeflow도 동일한 client/view를 공유해 영향이 있다고 판단한다. 메뉴 왕복이나 재연결로 우회할 수 있으므로 영구적인 참여 차단으로 과장하지 않는다.

[재현 코드](reproduction/reproduce-lead-edit.cjs) · [관찰 결과와 exact 소스 해시](reproduction/lead-edit-repro-result.json) · [검증 확인](verification.json).

수용 기준:

- 오류 후 이메일·동의를 수정해도 현재 폼에서 명시적으로 복구할 수 있다.
- 결과가 불명확한 기존 요청의 event ID와 원 payload를 보존하고, 편집한 draft와 구분한다. 동일 event ID에 다른 이메일을 넣지 않는다.
- 자동 lead 전송이나 가짜 완료를 만들지 않는다. 상태 확인·재시도·새 제출 중 실제 가능한 행동을 제공한다.
- 수정/무수정, 두 오류, 이미 서버에 접수된 응답 유실, 동의 세대 갱신을 관련 client/view 회귀로 고정한다. 두 주제의 실제 UI 복구도 확인한다.
- 작성자가 수정한 exact SHA와 관련 최소 검증 근거를 전달하면 같은 reviewer가 재검토한다.

## 나머지 검토 결과

R2 전용 CSS module은 기존 전역 스타일을 변경하지 않는다. 승인된 파랑·진한 글자·흰 보조 버튼·밑줄 행동, rem 글자, safe-area, 최소44px 조작 영역과 단일 문서 스크롤이 일관된다. MENU의 min-height 수정은 AP001 직접 화면 검증과 일치한다. Tailwind로 다시 작성하거나 앱 하단 탭을 추가할 이유는 없다.
