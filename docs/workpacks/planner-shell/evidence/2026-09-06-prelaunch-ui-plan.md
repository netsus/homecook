## 승인 범위

사용자는 배포 전에 UI만 정리하고 로컬에서 계속 확인하도록 요청했다.
현재 복원 작업의 `fix/restore-planner-interactions` 브랜치에서 이어서 수정한다.
이 문서는 별도 Stage 완료나 배포 승인이 아니다.

1. YouTube 새 추출 시도는 준비 중 안내. 기존 추출 결과 읽기/정리는 보존한다.
2. 비로그인 플래너는 명시된 공개 예시만 표시하고 추가/수정/삭제는 로그인 안내.
   개인 API/RLS/권한을 완화하거나 실제 사용자 데이터를 공개하지 않는다.
3. 반복 튜토리얼 토스트를 억제하고 `/beta`에는 앱 팝업을 표시하지 않는다.
4. 앱에 준비 안내를 표시한다. `/beta`의 자체 viewport는 보존한다.
5. 주간 카드의 중복 장보기/상세 버튼은 제거하고 카드 제목의 진입을 유지한다.
6. 데스크톱 상태 요약은 사이드바 한 곳에 색상과 함께, 탭은 왼쪽의 작은 크기,
   이번 주 버튼은 명확한 버튼 형태로 표시한다.
7. 사용자가 추가 첨부한 랜딩 식단 이미지 기준: 한 박스의 날짜 줄, 오늘 파란
   배경/흰 글씨, 날짜 카드 안의 4개 영양 타일, 굵은 음식명과 kcal/단백질,
   오른쪽의 작은 파란 +. 날짜 칩 안에 영양 숫자를 넣지 않는다.
8. 기존 선택일 식사 기록 화면에 일별 영양, 음식별 실제 양, 탄단지 그래프.
   요리 배치는 g, 제품/재료는 exact 환산이 가능한 기존 계약만 사용한다.
9. 계획 음식의 개별 영양은 현재 레시피가 아니라 고정 snapshot과 계획 인분을
   재사용하는 authenticated server-rendered view model로 제공한다.

## 사용자 후속 승인 — 밝고 간결한 플래너 재배치

사용자는 실제 모바일/데스크톱 확인 뒤 디자인·배치 재량과 중복 UI 삭제를 승인했다.
이번 로컬 수정은 위 UI 범위를 다음처럼 보완한다. API/DB/영양 계산 계약은 유지한다.

- 하늘색 포인트와 옅은 파랑 면, 읽기 쉬운 글씨를 조합한다. 큰 어두운 파랑 면은 제거한다.
- 데스크톱 주요 메뉴에서 요리 계획/식사 기록을 각각 제공하고 마이페이지는 프로필로 접근한다. 모바일 기존 하단 메뉴는 유지한다.
- 준비 배너·상단 메뉴·부가 작업은 일반 스크롤 흐름, 모바일 날짜 줄만 고정한다. 데스크톱 플래너는 일반 페이지 스크롤을 사용한다.
- 요리 계획 카드: 이름 + 만들 인분/준비 상태 두 줄. 영양은 상세에서 확인하며 계획과 실제 섭취를 혼동하지 않는다.
- 장보기/남은요리와 이번 주 요약은 간결하게 배치하고 최근 계획 중복 목록을 제거한다.
- 식사 기록: 일일 영양 그래프를 항상 표시, 끼니 카드와 중복 수정/삭제를 통합한다.
- 계획: 기존 권한/주 이동/추가/이력 테스트 보존 → 배치 수정 → 320/390/1280 실화면과 스크롤/링크 검증.

### 2026-09-06 주간 식사 기록·출시 전 가입 차단

사용자 승인: 식사 기록을 주간 세로 날짜 카드로 표시하고 최초 진입 시 선택일(기본 오늘)에 맞춘다. 날짜별 합계는 숫자가 파란 4개 영양 타일, 개별 식사는 양/kcal/탄단지 텍스트로 표시한다. 계획은 전체 kcal/탄단지와 막대를 표시한다. 완성 무게는 추후 수율 기반 예상값·실측 덮어쓰기를 개발할 예정이며 지금 알고리즘/DB 쓰기를 추가하지 않는다. 정보가 없는 계획은 ‘무게 계산 준비 중’으로 표시한다.

선택 날짜는 테두리 없는 파랑/흰 글씨, 오늘은 별도 라벨로 구분한다. 오늘·장보기·남은요리는 버튼 형태로 보강하고 상단 준비 배너를 한 줄 기준선으로 정렬한다. 홈 YouTube 진입의 복귀는 홈이다.

출시 전 소셜 로그인 버튼과 앱 로그인 시작/콜백을 차단한다. 시작은 기존 AUTH_FLOW_UNAVAILABLE/503, 콜백은 교환 전에 준비 안내로 반환한다. 기존 세션·로컬 password QA·인증된 계정 연결은 보존한다. Supabase 외부 직접 인증 API 설정을 변경하는 것은 범위 밖이다. 로컬 랜딩은 허용 origin·공식 캠페인 기간 설정 누락을 로컬 전용으로 보완하고 실제 저장 인증 오류와 구분한다. 새 계정/리드 저장 성공을 가짜로 처리하지 않는다.
