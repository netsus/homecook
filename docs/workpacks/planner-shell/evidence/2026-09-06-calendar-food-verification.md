# 날짜 즉시 선택 · 식사 그래프 · 가이드 이미지

## 변경 파일과 결과

- `components/planner/planner-date-controls.tsx`: 기본 날짜 입력창을 앱 내부 달력으로 교체했다. 날짜를 누르면 확인 단계 없이 닫히고 이동한다. 월·연도 선택, 윤년, 키보드 월 경계 이동을 지원한다. 입력창을 제거했으며 사용자의 핀치 확대는 제한하지 않는다.
- `components/planner/meal-log-screen.tsx`: 음식 이름을 눌러 상세를 열고, 그 안에서 기존 수정창으로 이동한다. 목록에는 휴지통 아이콘, 양·칼로리 숫자, 탄단지 비율 막대를 표시한다. 나트륨은 상세에만 표시한다. 서버의 칼로리는 그대로 사용하고 4/4/9 환산은 탄단지 비율에만 사용한다. 미확인·부분·0 값은 임의 보완하지 않는다.
- 공개 예시 상세는 읽을 수 있지만 수정은 로그인 안내를 거친다. 로그인 상태가 바뀌면 상세를 닫고 출처를 확인한다. 실제 수정은 인증된 최신 기록에서 항목을 다시 조회한 뒤 허용한다.
- `components/home/home-screen.tsx`, `app/globals.css`: 가이드 카드의 장식 SVG와 중복 문구를 제거했다. 랜딩 공유 metadata의 `/assets/funnel/share/og-share.png`를 원본 비율로 표시하며 기존 `/about#how-to` 링크를 유지한다.
- 관련 테스트와 기존 workpack·공식 문서의 후속 승인 내용을 보완했다. 신규 API·DB·route·의존성은 추가하지 않았다.

## 검증

- 관련 53개 파일: 51개 통과, 2개 환경 의존 생략. 테스트 591개 통과, 27개 생략. `/tmp/calendar-card-regression.log`.
- 전체 타입 검사, ESLint, SOT 문서 정합성, diff 공백 검사 통과. 최종 Next production build 통과(exit 0). `/tmp/calendar-card-build.log`.
- 달력의 즉시 선택·윤년·키보드 경계를 실패 테스트 3개로 확인한 뒤 모두 통과시켰다.
- 게스트에서 로그인 상태로 바뀔 때 예시 상세가 남는 문제를 재현한 뒤, 출처 검증과 최신 항목 조회로 수정했다. 관련 상세·충돌·인증 회귀 47개가 통과했다.
- Chromium과 WebKit의 320·375·1280px, 요리 계획·식사 기록 12개 조합을 확인했다. 선택 후 달력 닫힘, URL 날짜, 화면 배율 1, 스크롤 잠금 해제, 가로 넘침 없음, pageerror 없음이 확인됐다.
- 상세 읽기, 상세에서 수정 시 로그인 안내, 삭제 아이콘의 로그인 안내를 확인했다.
- 375px 홈에서 공유 이미지의 정상 로딩과 원본 비율 유지, 잘림 없는 표시를 확인했다.
- 보조 코드 리뷰에서 추가 P1/P2는 발견되지 않았다. 정식 Stage 승인을 의미하지 않는다.
- 화면과 브라우저 결과: `ui/designs/evidence/prelaunch-planner-ui/calendar-and-food/`. 로컬 시각 검토 95/pass.

## 검증 경계

현재 로컬은 공개 예시 미리보기다. 실제 계정 OAuth·저장 흐름 전체 검증과 운영 배포는 수행하지 않았다. WebKit 모바일 모드 검증을 실제 iPhone 13 mini 기기 검증으로 표현하지 않는다.

빌드는 비공개 환경파일을 복사하지 않은 별도 runtime copy와 가짜 loopback Supabase 값으로 수행했다. 전체 lint는 원본 저장소에서 별도로 실행했다.
