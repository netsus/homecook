# 요리계획·식사기록 재설계 초안

> 2026-10-06 사용자 후속: [얇은 막대·글자 굵기·반복 설명·팬트리 진입 기준](planner-meal-log-visual-rules-20261006.md)이 이전 시각 표현보다 우선한다.

상태: 아래 내용은 초기 설계 방향이다. 2026-10-05에 별도 세션의 독립 와이어프레임 검토 2회를 거쳐 최종 설계를 정리했다. [최종 모음](wireframes/20261005-planner-meal-log/reviewed-v2/index.html)과 [동작 규칙](wireframes/20261005-planner-meal-log/reviewed-v2/interaction-contract.md)이 우선한다. 중요한 미해결 P1/P2는0건이나, 이미지 픽셀 정밀도·실제 기기 사용성 검증과 앱 구현·배포는 별개다. 사용자 인터뷰/실제 기기 테스트를 수행한 결과로 오해하지 않는다.

## 설계 순서

1. 사용자가 하려는 일을 정한다. 대표 상황마다 필요한 정보·첫 행동·성공 기준을 적는다.
2. 정보를 ‘목록에 항상 표시 / 상세에서 표시 / 해당 상황에서만 표시’로 나눈다. 각 화면의 기본 보기와 이동 방식을 정한다.
3. 실제 제목·여러 음식·빈 날·로딩·오류를 넣은 모바일 설계안을 비교한다. iPhone 13 mini 너비 375px에서 큰 글자와 키보드까지 고려한다. 색상보다 정보의 위치와 동작부터 결정한다.
4. 선택한 설계대로 기존 컴포넌트를 수정한다. 대표 흐름과 화면을 묶어서 확인하고 사용자가 요청한 시점에 배포한다.

## 두 화면의 역할

| 구분 | 요리계획 | 식사기록 |
| --- | --- | --- |
| 사용자의 질문 | 언제 무엇을 몇 인분 만들까? 무엇을 준비해야 할까? | 오늘 무엇을 얼마나 먹었지? |
| 기준 | 예정 날짜·끼니, 만들 음식과 계획 인분 | 실제 먹은 날짜·끼니, 음식과 먹은 양 |
| 가장 중요한 행동 | 계획 추가, 재료 준비, 요리 시작/이어하기 | 먹은 음식 추가, 먹은 양 수정 |
| 목록의 핵심 정보 | 음식명, 인분, 준비/요리 상태 | 음식명, 먹은 양, kcal |
| 상단 보조 동작 | 장보기 | 남은 요리 |
| 영양 | 예상값. 상세에서 확인하는 방향을 우선 검토 | 하루 합계와 끼니 kcal. 탄단지 상세는 필요할 때 열기 |
| 기록 관리 | 계획 변경·삭제는 상세 | 먹은 양 수정·삭제는 상세 |

계획 인분과 개인 섭취량은 서로 다른 값이다. 같은 요리를 여러 사람이 나눠 먹거나 여러 끼니에 먹는 경우를 기본 시나리오로 다룬다. 요리 완료만으로 먹었다고 기록하지 않는다. 실제 섭취량과 연결된 남은 양 계산은 기존 데이터 계약을 유지한다.

## 먼저 검증할 대표 상황

| 상황 | 필요한 정보/행동 | 성공 기준 |
| --- | --- | --- |
| 이번 주 저녁을 미리 정한다 | 주간 빈 끼니, 음식 검색·저장한 레시피 선택, 인분 | 날짜를 잃지 않고 여러 날에 계획을 추가한다 |
| 여러 계획의 장을 한 번에 본다 | 장보기 가능한 계획, 묶음 선택, 생성/완료 상태 | 이미 장본 계획이 새 목록에 잘못 포함되지 않는다 |
| 오늘 요리를 시작하거나 이어 한다 | 오늘 음식, 준비 상태, 기존 요리 세션 | 새 세션을 중복 생성하지 않고 정확한 요리를 연다 |
| 만든 요리 일부를 먹었다 | 먹을 수 있는 남은 요리, 남은 양, 섭취량 | 한 끼를 기록하고 남은 양이 함께 맞는다 |
| 제품·재료 또는 이전 음식을 다시 기록한다 | 최근 음식, 검색 결과, 명확한 양 입력 | 검색→선택→양→저장이 끊기지 않는다 |
| 어제 기록을 고친다 | 날짜·끼니, 원래 먹은 양, 수정/삭제 | 복귀 시 같은 날짜와 위치를 유지한다 |

## 정보 배치의 첫 제안

### 요리계획

- 상단: 제목·알림, 날짜 선택·오늘·장보기.
- 모바일은 주간 날짜 줄로 이동하고 선택한 날의 끼니를 간결하게 보여주는 안을 먼저 검토한다. 한 주 전체를 연속으로 보는 대안도 비교해, 주간 식단을 한눈에 보는 장점이 사라지지 않게 한다.
- 음식 행은 이름·인분·텍스트가 함께 있는 상태 표시를 우선한다. 큰 영양 그래프의 반복은 상세로 옮기는 안을 검토한다.
- 끼니별 +는 음식 추가, 음식 행을 누르면 상세로 이동한다. 상세에서 인분·준비 상태·장보기·요리/이어하기를 제공한다.
- 캘린더/장보기 기록/주간 상태 합계는 핵심 행동을 밀어내지 않는 보조 위치에 둔다.
- 데스크톱은 한 주를 비교하기 쉬운 표를 활용하되 정보 우선순위와 상태 의미는 모바일과 같다.

### 식사기록

- 상단: 제목·알림, 날짜 선택·오늘·남은 요리.
- 선택한 날의 합계는 kcal를 우선하고 탄단지는 간결하게 표시한다. 목표 대비 표현은 사용자가 목표를 설정한 경우에만 별도 설계한다.
- 끼니 행: 이름, 오른쪽 kcal, +. 음식 행: 이름, 먹은 양, 오른쪽 kcal.
- 목록 삭제 버튼과 반복 설명·반복 영양 그래프는 줄인다. 상세에서 수정·삭제한다.
- 음식 추가는 최근 음식 / 요리한 음식 / 제품·재료로 빠르게 찾는다. 다 먹은 요리는 제외하고, 무게가 없는 음식에는 필요한 다음 행동만 표시한다.
- 주간 추이는 별도 보조 보기로 검토한다. 처음부터 일주일치 긴 상세 기록을 모두 읽게 만들지 않는다.

## 공통 설계 기준

- 한 화면의 대표 행동을 눈에 띄게 하고, 부가 기능은 상세나 더보기로 이동한다.
- 고정 요소는 필요한 만큼만 사용한다. 작은 폰에서 본문·모달의 이중 스크롤이나 키보드 위 버튼 겹침을 만들지 않는다.
- 입력값은 빈칸을 허용하고, 표시용 정수 반올림이 실제 저장·계산 정밀도를 바꾸지 않게 한다.
- 상태는 색상만으로 구별하지 않는다. 버튼은 최소 44px 터치 영역과 명확한 이름을 갖는다.
- 날짜 이동, 뒤로가기, 상세 닫기 후 위치를 보존한다. 지연 응답은 스켈레톤으로 표시하며 인증 오류로 간주하지 않는다.
- 빈 화면·검색 결과 없음·저장 실패에는 다음 행동을 제공한다. 실패해도 입력 내용은 남긴다.
- 기존 소유권·멱등성·계획/장보기/요리/섭취 상태 계약은 유지한다. UX 편의를 위해 서로 다른 기록을 자동으로 같은 상태로 바꾸지 않는다.
