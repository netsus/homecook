# 독립 검토에 대한 수정 판단

2차 독립 재검토에서 design_ready=true를 받았다. 중요한 미해결 P1/P2는0건이며, 이미지 픽셀 정밀도 관련 선택적P3 한 건은 구현 시 공통 계산으로 해결한다. 실제 앱 구현·배포 승인이나 실제 기기 검증 완료를 의미하지 않는다.

- WF-001 수용: 01·05·07은 김치찌개 14g/23g/18g의 4/4/9 환산 열량 56/92/162, 총310kcal, 약18.1%/29.7%/52.3%를 사용한다. 양만250g으로 바꿀 때 구성비는 유지한다. 06의 축은 kcal0/200/400/600/800, 단백질g0/10/20/30/40의 동일 간격으로 바꿨다. 단일 예시 데이터는 fixture-data.json이다. 저녁의160kcal 음식은 점심 현미밥과 다른 음식인 볶음밥으로 표시해 양만 바뀐 동일 음식이라는 오해를 없앤다.
- WF-002 수용: 선택한 날에 모든 설정된 끼니(예시 아침·점심·저녁)의 제목과+를 표시한다. 빈 아침도 한 줄로 남긴다. 주간 목록의 빈 날짜+는 >로 바꿔 ‘그날 선택→해당 끼니+’로 흐름을 하나로 정한다.
- WF-003 수용: 끼니 제목에 >를 붙였다. 제목 영역은 끼니 상세, 음식 행은 그 계획한 음식 상세, +는 끼니 추가로 분리한다. 제목과+의 클릭 영역은 겹치지 않는다.
- WF-004 간결한 대안으로 수용: 목록 전체에 ‘열량 구성비’와 도움말 버튼을 한 번 둔다. 상세/양 입력에도 짧은 제목을 쓴다. 매 음식 행의 설명 문장을 늘리는 방식은 채택하지 않는다. 도움말 내용은 ‘색 비율은 탄수화물·단백질·지방에서 나온 열량 비율이에요. 막대 전체 길이는 섭취량이 아니에요.’이며 g구성비와 구별한다.
- WF-005 효과 중심 대안으로 수용: 요리한 음식의 기록 삭제 확인에는 ‘기록한300g이 남은 양으로 돌아갑니다’를 추가한다. 확인 전 최종 잔량600g을 고정 단정하는 방식은 동시 수정 때문에 채택하지 않는다. 제품/재료 기록에는 잔량 복원 문구를 넣지 않는다. 실제 복원 가능 여부·충돌은 서버 응답으로 확인한다.

원래 파일은 보존했다. 02·03·04는 변경하지 않았고 01·05·06·07·08을 수정했다. 07의 같은 끼니 추가+도 명시했다. 모든 수치는 가상 설계 데이터이며 실제 식품의 공인 영양값이 아니다. 래스터 와이어프레임의 글자/픽셀 오차와 구현의 데이터 계산·단위 규칙은 구분하며, 잘못된 관계를 정당화하는 근거로 삼지 않는다.
