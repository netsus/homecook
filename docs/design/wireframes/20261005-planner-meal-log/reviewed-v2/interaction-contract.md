# 최종 검토용 동작 규칙

## 날짜·끼니·복귀
- 요리계획 주간 행을 누르면 날짜를 선택하고 해당 날짜의 모든 설정된 끼니 제목과+를 표시한다. 빈 날짜도 같은 동작이다. 기본 예시는 아침·점심·저녁이며 사용자 설정에 맞춘다.
- 끼니 제목은 끼니 상세, 음식 행은 해당 계획한 요리 상세, 독립된+는 그 날짜·끼니의 추가 모달을 연다.
- 뒤로는 들어온 화면의 날짜·스크롤 위치·초점을 복원한다. 추가 성공은 원래 끼니 목록, 수정 성공은 갱신된 음식 상세, 삭제 성공은 같은 날짜 목록의 가까운 항목으로 돌아간다.

## 모달·입력·키보드
- 추가·수정은 기존 화면이 배경에 남는 모달이다. 내용이 길거나 키보드가 열리면 확장하지만 배경의 맥락을 남긴다. 모달 안 스크롤은 하나이며 배경 스크롤을 잠근다.
- 키보드 위에 글로벌 탭이나 큰 별도 저장 패널을 띄우지 않는다. 키보드가 열려도 입력·오류·양 미리보기·저장 버튼까지 모달 내부 스크롤로 접근 가능해야 한다. 키보드 ‘완료’는 닫기이며 저장으로 오해하게 만들지 않는다.
- 숫자 입력은 빈칸과 소수 입력 중간 상태를 보존한다. iOS 확대 방지를 위해 입력 글자를16px 이상으로 하고 직접 핀치 확대는 허용한다.
- 변경 없는 닫기는 즉시, 변경한 입력이 있으면 한 번의 버리기/계속 편집 확인을 한다. 내부 뒤로는 검색어·탭·선택·초안을 보존한다. 반복 중첩 모달을 만들지 않는다.
- 44px 클릭 영역, 포커스 이동, 스크린리더 이름, 대비, 이중 스크롤 여부는 구현 후 실제375px/iPhone13 mini에서 검증할 항목이다. 정적 그림으로 통과했다고 주장하지 않는다.

## 저장·실패·상태
- 저장 중 중복 누르기를 막고 응답이 불확실한 같은 시도는 같은 멱등키로 재시도한다. 성공 확인 전 토스트·닫기·낙관적인 잔량 확정을 하지 않는다.
- 실패 시 선택 날짜·끼니·음식·입력량을 보존하고 수정/재시도를 제공한다. 409는 최신 상태를 확인해 선택을 다시 받는다. 느린 응답을 인증 오류로 표시하지 않는다.
- 등록·미연결은 장보기, 장보기 연결 중은 기존 목록, 장보기 완료는 요리 시작, 정확한 활성 세션이 있으면 이어하기, 완료는 완성 음식 보기다. 독립 요리와 계획 상태를 섞지 않는다.
- 장보기 진행 후 인분 변경은 기존 영향 확인/권한 계약을 따른다. 완료 장보기는 읽기 전용이다. 수정 불가 상태는 숨기거나 비활성+짧은 이유를 제공한다. 원본 레시피가 수정되어도 계획은 저장된 내용으로 이어간다.

## 음식 후보와 단위
- 소진된 요리는 최근/요리한 음식에서 제외한다. 선택 후 잔량이 바뀌면 최신 값과 입력 수정/다시 선택 경로를 제공한다.
- 무게 없는 요리는 ‘무게 입력 필요’ 동작을 제공하며 근거 없는 잔량·영양값을 만들지 않는다. 제품·재료는 저장된 기준이 지원하는 단위만 제공하고 g↔개 환산을 임의로 하지 않는다.
- 최근 없음은 다른 탭을 계속 쓸 수 있게, 검색 결과 없음은 검색어 수정·지우기 동작을 제공한다. 로딩은 스켈레톤, 검색 결과 없음과 구별한다.
- 다른 계정의 늦은 결과는 버린다. 로그인 복귀 시 대상과 권한을 재확인하며 보호를 우회하지 않는다.

## 영양·잔량
- 음식의 짧은 막대는 열량 구성비다. 계산 비율은 반올림 전의 탄수g×4, 단백g×4, 지방g×9로 구한다. 이 비율은 같은 음식의 양만 바뀌면 유지한다. 화면의 정수 표시는 저장·계산의 정밀도를 줄이지 않는다.
- 하루 열량 그래프의 길이는 kcal, 영양소 선택 후에는 g이며 모두 같은0점과 일정 눈금을 쓴다. 가상 예시는 fixture-data.json에서 음식→끼니→하루 합을 검산한다.
- 실제 데이터의 식품표기 열량과4/4/9환산합이 다를 수 있다. 구성은 환산 열량의 비율로, 막대 총길이는 기록된 kcal로 표현하고 성분 조각의 실제kcal라고 단정하지 않는다. 도움말로 계산 기준을 구별한다.
- 영양정보가 일부 없으면0이나완전한100% 구성으로 꾸미지 않는다. 해당 막대는 일부 정보 상태로 대체하고, 합계도 ‘확인된 정보 기준’으로 구별한다. 기록 없음은0이 아니라 기록 없음이다.
- 요리한 음식과 연결된 섭취 기록 삭제는 섭취량을 되돌린다. 확인창은 복원량을 보여주고 최종 잔량은 성공 응답으로만 확정한다. 제품/재료 기록에는 이 안내를 넣지 않는다. 삭제와 실제 음식 버림은 합치지 않는다.
