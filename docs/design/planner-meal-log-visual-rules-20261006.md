# 요리계획·식사기록 시각 기준 — 사용자 후속 결정

2026-10-06. 사용자 피드백에 따른 구현 기준이다. 이후 [설계 적용 작업](../engineering/planner-meal-log-redesign-20261006.md)에서 UI에 반영했으며 운영에는 배포하지 않았다. 이전 와이어프레임의 굵은 글씨·막대 두께와 상시 설명 표시는 그대로 복사하지 않는다. 기존 독립 검토는 이전 버전의 흐름에 대한 기록이며 이 후속 변경의 재검토를 의미하지 않는다.

## 막대와 정보 배치

- 음식별 탄단지 막대는 B 초안처럼 얇게 한다. 모바일 실제 CSS 높이 **4px**를 시작값으로 하며 화면 확인 시 4~5px 범위에서 조정한다. 하루 영양 상세의 비교 그래프까지 일괄적으로 4px로 만들지 않는다.
- 음식명은 왼쪽, kcal는 오른쪽에 정렬한다. 먹은 양은 음식명 아래, 막대는 독립된 줄, 탄단지 수치는 그 아래에 둔다. 정보가 늘면 세로 스크롤을 사용하고 한 화면에 모두 넣으려고 여백·글자를 줄이지 않는다.
- 탄수화물 하늘색 `#94C9FF`, 단백질 분홍색 `#FFA7C2`, 지방 노란색 `#FFD477`을 유지한다. 계산과 비율은 기존 동작 규칙·공통 데이터가 기준이다.
- 막대는 시각 표시이며 클릭 영역을 막대 두께로 축소하지 않는다. 음식 행·버튼의 접근 가능한 터치 영역은 유지한다.

## 글자 굵기 — 전체 화면에 적용

| 역할 | 기본 굵기 |
| --- | --- |
| 일반 본문, 음식별 kcal·g, 보조 정보 | 400 (보통) |
| 음식명, 끼니명, 입력 라벨, 버튼 문구 | 500 (중간) |
| 화면 제목, 하루 핵심 합계 | 600 (약간 굵게) |

- 700·800을 제목·음식명·숫자·버튼에 일괄 적용하지 않는다. 모든 숫자나 모든 제목을 강조 대상으로 취급하지 않는다.
- 하루 총 kcal는 크기로 강조하고, 끼니 합계는 위치·크기로 구별하되 기본 500을 쓴다. 수치 뒤 kcal/g 단위는 보통 굵기로 둘 수 있다.
- 중요도는 크기·여백·정렬로 먼저 구분한다. 가늘게 보이게 하려고 본문 색 대비나 글자 크기를 과하게 낮추지 않는다. 모바일 입력은 16px 이상을 유지한다.
- 이는 요리계획, 식사기록, 상세, 추가/수정/확인 모달에 공통 적용한다. 다른 앱 화면도 후속 구현 시 같은 과도한 굵기를 점검하되 이번에 전체 앱 코드를 일괄 수정한 것은 아니다.

## 반복 설명 정리

- 식사기록 목록에서 별도 `열량 구성비` 설명/범례 줄을 제거한다. 각 음식의 탄단지 수치와 색상으로 읽게 한다.
- 먹은 양 입력은 `300g 기준`, 음식 상세는 `먹은 양 기준 영양` 정도의 짧은 맥락만 둔다. `열량 구성비` 문구를 여러 화면에 반복하지 않는다.
- 계산 기준은 하루 영양 상세의 정보 버튼을 눌렀을 때 한 번 제공한다. 상시 설명을 제거해도 kcal와 g 단위, 누락된 영양정보 구별은 유지한다.

## 기존 기능 보존

- 요리계획 추가에는 레시피 검색·레시피북·**팬트리에서 찾기**·유튜브·직접 등록의 다섯 경로를 보존한다. 팬트리 경로는 앱에 이미 존재하며 이전 와이어프레임에서 누락한 것이었다.
- 팬트리는 보유 재료로 레시피를 찾는 경로다. 선택 경로가 달라도 날짜·끼니는 인분 확인과 저장까지 보존한다.
- 최근 완성된 후속 이미지는 [참고 파일 목록](wireframes/20261005-planner-meal-log/user-feedback-20261006/manifest.json)에 보관했다. 해당 이미지의 굵기·두께·반복 설명과 본 문서가 다르면 이 사용자 결정이 우선한다.

## 구현 때 확인

375px 화면에서 음식명·kcal가 구별되고 얇은 막대의 색도 읽히는지, 굵은 요소가 연속해서 경쟁하지 않는지 확인한다. 입력·버튼의 실제 크기와 접근성을 유지한다. 기존 그림 전체를 다시 생성하는 것이 이 결정 반영의 선행 조건은 아니다.
