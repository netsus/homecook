# 레시피 검색·중복 정리 — 2026-09-27

상태: 피드백 묶음의 로컬 수정. 커밋·머지·배포 및 운영 데이터 변경은 아직 하지 않았다.

## 검색 변경

- 홈 입력창은 제목·승인된 공개 태그뿐 아니라 실제 `recipe_ingredients`의 표준 재료명과 별칭을 검색한다. 화면의 이름도 `제목·재료 검색`으로 맞춘다.
- 일반 `돼지고기`/`돼지` 검색과 일반 돼지고기 ID 선택은 돼지고기 부위 이름·승인 별칭 및 명시적인 돼지 부위 이름으로 확장한다. 육류 분류를 함께 확인해 돼지감자·소고기 목심 등을 섞지 않는다. 특정 부위를 선택하면 무조건 돼지고기 전체로 넓히지 않는다.
- 검색용으로 관련 ID를 묶을 뿐 재료 ID·영양·과거 snapshot을 합치거나 수정하지 않는다. 선택 재료 그룹 내부는 OR, 여러 선택 그룹 사이는 AND다.
- 재료 모달에서 적용하면 이전 검색어와 테마/태그를 제거해 선택 재료로 새 검색을 시작한다. 별도의 재료 필터 초기화 버튼은 기존 검색어를 유지한다.
- 현재 `/ingredients` 구현은 정규화된 `search_name`, 별칭 문자열, `id` 보조 정렬과 1,000행 페이지 조회를 사용하지만 공개 접근 검사는 과거 요청 모양만 허용해 비로그인 조회를 409로 거부했다. 기존 공개 필드와 GET 범위 안에서 현재 요청 모양을 허용한다. wildcard·사용자 테이블·쓰기·과도한 페이지 크기는 허용하지 않는다.
- ID 목록은 100개 단위, 재료 매핑은 1,000행씩 끝까지 조회한다. 요청 안에서만 조회를 재사용하며 공개·미삭제·소유자 공개 가능 조건과 정렬·cursor를 유지한다. 조회 실패를 빈 성공 결과로 숨기지 않는다.
- 검색 결과가 없으면 초기화 외에 `레시피 직접 등록`(`/menu/add/manual`)과 `유튜브로 가져오기`(`/recipes/new/youtube`)를 제공한다. 기존 목적지의 로그인과 복귀 경로를 사용한다.

## 읽기 전용으로 확인한 운영 상태

- 일반 돼지고기, 돼지고기 목심, 돼지고기 앞다리, 삼겹살은 서로 다른 재료 ID다. 이들을 사용하는 공개 레시피는 현재 5개다. 기존 일반 돼지고기 ID 단독 조회는 부위 ID를 포함하지 않았다.
- 실제 된장 ID `a979f352-5a8e-46e5-9d21-53f5b6ffc8d1`는 된장국과 새우아욱죽에 연결되어 있다. 기존 운영 레시피 API에 이 ID만 전달하면 두 개가 정상 반환됐다. 따라서 된장 데이터 자체가 없다고 판단하지 않는다. 이전 검색어 혼입과 비로그인 카탈로그 조회 거부를 각각 수정한다.

## 검증

- 실제 Supabase SDK가 만드는 조회 URL과 공개 접근 규칙을 함께 검사한다. 돼지고기 부위/비육류 제외, 된장, 여러 재료 교집합, 별칭·공백, 1,000행 뒤의 결과, 오류 전파와 미리보기 재료 일치를 확인한다.
- 기존 API 계약/제목·태그 정렬·cursor 검사와 홈 UI 회귀 검사, 타입·수정 파일 정적 검사를 실행한다.
- 별도 읽기 전용 검토에서 공개 데이터 범위·요청별 캐시·페이지 누락·오류 처리의 차단 결함이 발견되지 않았다.
- 일회성 SQL 실행과 실제 운영 검색 결과 확인은 묶음 반영 단계에 남겨둔다. 이번 작업에서 운영 백업·복원·자동 시작 검사를 실행하지 않는다.
