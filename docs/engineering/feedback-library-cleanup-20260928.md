## 여섯 항목의 결과

1. 남은 요리의 기존 목록과 중량 목록을 하나로 통합했다. 레시피 제목/날짜·인분/남은 g와 식사 기록 버튼만 기본 표시한다. 무게 수정·남은 양 수정·버림은 `⋯` 관리 메뉴에 모았다. 관리 메뉴는 카드 안에서 펼쳐져 하단 탭에 가리는 별도 떠 있는 패널을 만들지 않는다. 실제 무게를 모르는 새 음식은 무게 입력을 제공하며 수치를 꾸며내지 않는다. 소진 음식은 남은 목록에서 제외한다.
2. 모바일은 화면 높이 안에서 헤더와 탭을 유지하고 본문 한 곳만 스크롤한다. 기존의 계산된 컨테이너 높이/외부 문서 스크롤 조합을 제거했다. 다른 화면으로 나가면 문서 잠금을 해제한다.
3. 남은 요리, 중량 관리, 요리 완료, 재료 선택, 식사 기록, 연결된 로그인 방법, 탈퇴의 반복 설명·내부 처리 설명을 줄였다. 날짜·인분·잔량 등 실제 값과 전체 무게/남은 양 구분, 복구할 수 없는 삭제, 식사 기록 없이 정리한다는 결정에 필요한 안내는 남긴다.
4. 레시피북 목록의 saved/custom/liked 개수는 상세 목록과 동일한 `recipes!inner(id)` 조회를 사용한다. 삭제되었거나 열람할 수 없는 레시피의 연결만 남은 행은 개수에서 제외한다. custom 북 수정 응답도 같은 기준으로 계산한다. 사용자 소유권과 레시피 RLS는 유지한다.
5. 레시피북의 요리 링크가 예전 standalone 화면을 직접 열고 있었다. 기존 `/cooking/recipes/{id}/cook-mode` 주소를 최신 고정 레시피 세션의 진입 화면으로 바꿨다. 현재 revision·인분·동일 요청 키로 시작하며 불확실한 응답은 같은 키/내용으로 재시도한다. 요리 완료창을 열기 직전에 현재 팬트리를 다시 읽는다. 차감이 404/409/422로 거절되면 최신 목록을 확인해 사라진 선택을 제거하며 실패를 성공으로 표시하거나 자동으로 재차감하지 않는다.
6. 탈퇴 API client가 필수 `Idempotency-Key`를 보내지 않았다. UUID를 보내고 화면의 중복 클릭을 막으며 실패 후 재시도에도 같은 키를 보존한다. 서버의 필수 키·세션·계정 보호 조건은 변경하지 않았다. 실제 사용자 계정을 탈퇴시키는 운영 테스트는 하지 않았다.
