## 삭제하지 않고 남겨 둔 선택 통합

영양/환산 이력이 있는 항목은 기존 `DELETE_NOT_ALLOWED` 보호와 FK를 유지했다. 이를 지우기 위해 트리거·권한·참조 보호를 완화하지 않았다.

다음105개는 **운영 선택 목록에서 아직 제외하지 않았다.**

- 미사용 약용·희귀·과도한 세분 항목86개
- 동일 식품·동일 원자료를 가진 미사용 중복 쪽19개

중복 예시는 알배추/알배기, 백도/백도 복숭아, 닭가슴살/닭고기 가슴, 케첩/토마토 케첩이다. 같은 원자료를 공유하더라도 의미/형태가 다른 황태/황태채, 파슬리가루/말린 파슬리, 국간장/재래간장은 자동 통합하지 않았다. 양쪽에 사용 흔적이 있는 쪽파 등도 보류했다.

로컬 `lib/ingredient-catalog-policy.ts`와 신규 migration의 제외 ID는 기존26+신규105=131개로 동기화돼 있다. 중복19개의 옛 이름은 이름 금지 목록에 넣지 않았다. 대표 재료의 정확한 별칭으로 계속 인식해야 하기 때문이다.

**ID 제외만 먼저 배포하면 안 된다.** 운영 적용 전 현재 사용/JSON 참조를 다시 확인하고,19쌍의 원래 이름·유효 별칭을 대표 재료에 연결해야 한다. 순차 상태 정규화의 새 표현도 교정된 기존 재료를 찾도록 별칭 연결이 필요하다. 그 데이터 정리와 SQL/TypeScript 선택 정책을 웹 반영과 같은 묶음으로 처리한다. 그 전에는 중복 통합 완료 또는105개 숨김 완료로 표현하지 않는다.

상세 항목과 필요한 별칭은 [미반영 선택 통합 계획](data/ingredient-catalog-selection-pending-20261006.json)에 있다. 현재 운영 SQL 선택 정책은 기존26개 제외 상태다.

## 검증

- 정확한 full-local 컨테이너·이미지 digest·볼륨·로컬 Unix socket을 확인했다. 원격/Cloud DB는 사용하지 않았다.
- 변경 직전 DB 전체 백업116,697,442bytes를 새 소유자 전용 파일로 만들고, 네트워크 격리 PostgreSQL에 전체 복원했다.
- 직접 FK12개를 실행 시점에 탐색해 확인하며 별칭 외 참조가 있으면 전체 작업을 중단한다. 별칭은 삭제 전 감사 기록으로 보존한다.
- 비FK `shopping_list_items.unavailable_ingredient_id`와 public/private의 JSON42개 컬럼을 추가 확인했다. 특히 레시피 삭제 후에도 남는 비공개 생성 요청 영수증을 포함했다. 원자료 provenance, 운영 감사 로그, 제품의 단위 관계 JSON은 실제 사용자 재료 참조와 구분했다.
- 사용자 기록을 담는 참조 테이블은 SHARE 잠금 후 검사한다. 읽기 전용 추출 모델 설정표는 ACCESS SHARE로 읽기 검사만 수행하며 권한을 늘리지 않았다.
- 실제 운영과 같은 **postgres 역할**로 이전 행 변경 감지, 후반 별칭 오류의 전체 취소, 새 FK 참조가 생기면 삭제 중단, 비공개 생성 영수증에만 참조가 있어도 삭제 중단을 복제본에서 확인했다.
- 18개 삭제·33개 이름·11개 분류·단위 정정 및 영양/기록 불변을 확인했다. 재실행 추가 변경0건이다.
- 관련4파일 **72검사 통과**. 기존 사전 테스트의 mock에 빠진 `search_name`을 현재 DB 검색 계약에 맞춰 보완했다. 기존 정책을 주입해도 같은 실패가 재현돼 신규 선택 정책의 회귀가 아님을 확인했고 제품 검색 코드·권한은 바꾸지 않았다.
- `git diff --check`, 렌더러 구문 검사 통과. 웹을 배포하거나 실제 화면을 검증한 결과는 아니다.

입력은 [고정된 정리 JSON](data/ingredient-catalog-cleanup-20261006.json), 실행 결과·백업 checksum은 [검증 결과](data/ingredient-catalog-cleanup-20261006-result.json)에 있다. `node scripts/render-ingredient-catalog-cleanup-20261006.mjs`는 checksum을 검증해 SQL만 출력하며 DB에 접속하지 않는다. 실제 실행은 확인된 로컬 대상·백업과 운영 절차를 전제로 한다. 삭제 행과 별칭, 변경 전 이름/분류는 운영 감사 이벤트와 백업에 남아 있다.
