# 남은 재료 정체성 확인과 영양 연결

상태: 운영 DB·웹 반영과 최종 집계·모바일/데스크톱 확인 완료.

## 원문 확인과 사용자 선택

남은 미연결9종11행을 원문·공식 조리사진·공개 영상·기존 데이터로 다시 확인했다. 브랜드를 확인했다고 주장하지 않고, 제품 정보가 없는 경우 검증한 제조사 표시자료 전체를 서비스 대표 예시로 사용한다. 물리적인 재료량·단위는 바꾸지 않는다.

| 원래 재료 | 처리 기준 |
| --- | --- |
| 신김치2행 | 두 영상에서 배추김치 확인. 김치찌개와 제육 모두 기존 배추김치로 연결. 제육은 사용자 선택대로 **세척 전200g 기준**을 유지하고 세척손실을 추정 차감하지 않음 |
| 김치국물 | 영상에서 같은 배추김치의 희석 전 국물 확인. 별도 배추김치국물 재료와 검증한 제품 대표값 사용 |
| 어린이치즈 | 공식 원문·사진의 어린이 슬라이스 형태. 검증한 어린이슬라이스치즈 제품을 별도 서비스 대표로 사용 |
| 알룰로스 | 사용자가 액상으로 확인. 액상 제품 대표 사용. 100g당2kcal를0으로 바꾸지 않고10g은0.2kcal로 계산 |
| 버섯2행 | 사용자가 새송이버섯 대표를 선택. 기존50g·80g과 원문 표현 보존 |
| 호박·옥수수 | 사용자가 애호박·통조림 스위트콘 대표를 선택. 기존50g·30g과 원문 표현 보존. 기존 가당 통조림 자료가 배액 전후를 명시하지 않아 배액 기준의 정확값이라고 주장하지 않음 |

| 화이트크림 | 생크림과 별도로 사용하는 원료이지만 배합·제품 불명. 생크림이나 크림소스로 임의 대체하지 않음 |

김치 조사 JSON에 남아 있는 세척 후 중량 제안은 당시 검토안이며, 사용자 최종 선택인 **세척 전 배추김치200g**이 이를 대체한다. 대표 선택과 세척 전 기준은 해당 레시피 설명에도 기록한다. 원래 외부 출처·조리 단계는 보존한다. 일부 저장량이 영상의 표현과 다르거나 정량 근거가 없는 경우에도 사용자가 변경한 값일 수 있어 이번에는 입력량을 그대로 사용했다.

## 제품 자료와 계산 연결 교정

공식 가공식품 원본 XLSX SHA256 `b074d98e75d2d087dc1b193f0056affbf9afd14524c9ccb556cb2b20978504f7`에서 어린이슬라이스치즈132729행·숙성김치국물159499행·액상알룰로스50219행을 확인했다. 각100g 기준·제조사·제품보고번호·영양7종이 기존 자료와 일치한다. 식약처가 수집한 제조사 표시자료이며 실측 분석자료로 부르지 않는다. 미기재 식이섬유는 null로 유지한다.

이번 통합 검증에서 앞서 추가한 제품 대표6개와 새3개의 `as_labeled` 형식이 재료 계산기에서 선택되지 않는 문제를 발견했다. 재료 계산기는100g 또는100ml 정규화 형식을 요구한다. 새3개는 `mass_100g`로 생성하고, 기존6개는 원래 기준량·영양값을 보존한 후속 프로필로 교체했다. 바닐라 페이스트는100ml 그대로 `volume_100ml`이며 밀도 없이100g으로 바꾸지 않는다. 기존 승인 프로필·연결은 허용된 상태 메타데이터만 superseded로 전이하며, 원자료 payload·기존 영양값·과거 기록을 보존한다. 실제 제품 라벨 프로필의 `as_labeled`는 정상 계약이므로 수정하지 않는다.

과거 `nutrition-completion-batch-20261010` 계획은 당시 적용 기록으로 보존한다. 해당 제품 복사 방식을 새 작업에 그대로 재사용하지 말고 이번의 계산 기여 검사를 함께 사용한다. 이전 완료 기록의 '제품 대표 등록'이 실제 계산 가능성까지 증명하지 못했던 점은 이번 후속 기록으로 정정한다.

## 검증 범위

새 전체 DB 백업을 격리 환경에 복원했다. 승인 프로필을 제자리 수정하거나 DB 보호를 완화하지 않았다. 기존 자료·기록 보존, 실패 시 전체 취소, 반복 적용 시 추가0을 확인한다. 모든 제품 대표9개를 실제 DB 조회→계산 경로로 넣어 원래100g/100ml 열량과 맞는지 검사한다. 예: 어린이치즈20g65.6kcal, 배추김치국물100g20kcal, 액상알룰로스10g0.2kcal.

대표 영양 안내의 새 데이터셋을 명시 목록에 추가했다. 영양 출처와 중량 출처는 구분한다. 변경된 화면·실제 API·최종 운영 집계는 아래 완료 결과로 기록한다.

## 운영 반영 결과

대상은 현재 레시피53개·재료516행이다. 전체 재료 카탈로그가 모두 완비됐다는 뜻은 아니다.

| 항목 | 반영 전 | 반영 후 |

| 핵심 영양 계산 완비 레시피 | 40 | 46 |
| 일부만 계산되는 레시피 | 13 | 7 |
| 영양 자료 미연결 행 | 11 | 2 |
| 확인된 단위 환산 누락 행 | 0 | 0 |
| 적당량으로 계산 제외된 행 | 9 | 9 |

부가 결측67개는38행·23재료에 걸쳐 있다. 기존 값을 지운 것이 아니라 새로 연결된 대표 자료의 미기재 식이섬유 등이 집계에 드러나62→67이 됐다. 핵심 계산 완비46개에도 일부 부가 영양소는 없을 수 있다.

영양 미연결은 **화이트크림·액체 해물육수** 각1행이다. 제품 표시나 배합·농도가 확인되면 보완한다. 적당량9행은 중량이 정해져야 계산할 수 있다. 현재 환산 누락0은 저장된516행을 확인한 결과이며 앞으로 모든 단위를 지원한다는 보장은 아니다.

한 트랜잭션으로 기존 대표6개 계산 연결을 교정하고, 정확한 형태의 재료4개·영양 대표3개·별칭1개를 추가했다. 현재9레시피10재료행을 교정하고 영양 저장본9개·내용 저장본9개를 추가했다. 수량·단위·외부 원문·조리 단계·과거 식사 및 영양 기록은 보존했다. 카탈로그1,936개·별칭4,180개·DB 원장216개이며 AI 자동 호출은 계속 비활성이다. worker와 권한도 변경하지 않았다.

## 화면과 검사

기존 설명 데이터를 모바일·데스크톱의 접힌 ‘레시피 설명’으로 재사용한다. 별도 설정이나 API를 추가하지 않고 대표값·세척 전 기준을 확인할 수 있게 했다. 새 대표자료도 영양 상세의 대표값 안내에 포함한다.

- 관련 화면·영양 검사96개, 데이터 계획·교정 검사22개, 타입 검사와 변경 파일 ESLint 통과.

- 범위를 넓혀 실행한 개인 레시피 액션 정적 검사1개는 기존 삭제 이동 동작에 없는 `router.refresh()`를 요구하여 실패했다. 이번 변경과 무관한 삭제 코드는 바꾸지 않았다. 위96개와는 별도다.
