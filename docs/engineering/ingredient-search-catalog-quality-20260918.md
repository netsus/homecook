# 재료 검색과 카탈로그 품질 정리 — 2026-09-18

현재 full-local DB를 읽기 전용으로 조사했다. 영양값이나 재료 참조를 임의로 바꾸지 않는다.

## 실제 발견한 규모

| 항목 | 수 |
|---|---:|
| 전체 재료 | 1950 |
| 선택 가능한 재료 | 1924 |
| 승인된 활성 대표 영양 profile 연결 없음 | 360 |
| 그중 실제 레시피에서 사용하는 재료 | 30 |
| 해당 레시피 재료 행 | 36 |
| 연결은 있으나 탄수화물·단백질·지방 값 일부 누락 | 7 |
| 공백 정규화 후 표준명 자체 중복 그룹 | 0 |
| 하나의 이름이 여러 ID를 가리키는 표준명/동의어 키 | 147 |
| 기본 단위가 빈 재료 | 1769 |

147개 모두 같은 종류의 오류라는 뜻은 아니다. `뿌리`, `줄기`, `수입산`처럼 재료 자체가 아닌 속성이 별칭으로 들어간 경우와, `국간장`이 표준명과 다른 일반 간장의 별칭에 동시에 있는 경우를 구분해야 한다.

## 이번에 고친 검색 규칙

1. 화면에 보이는 이름은 보존하고 별도 검색키만 NFKC·소문자·공백 제거로 만든다. `돼지 앞다리살`, `돼지앞다리살`, 전각 공백 표기를 같은 검색키로 찾는다.
2. 정확한 표준명을 먼저 사용한다. 표준명이 없으면 승인된 동의어를 사용하고, 여러 ID가 남으면 자동 연결하지 않고 후보로 보여준다.
3. `돼지 앞다리`, `돼지고기 앞다리살`을 확인된 `돼지 앞다리살`의 별칭으로 연결한다. 기존 다른 ID와 충돌하면 자동 추가하지 않는다.
4. 신규 재료 등록도 같은 정규화·별칭 조회와 동시 등록 잠금을 사용해 띄어쓰기 차이로 새 ID가 생기지 않게 한다.
5. 조회 오류는 빈 검색 결과로 숨기지 않는다. 검색과 직접 추출·비동기 추출·식사기록의 재료 연결 규칙을 맞춘다.

`돼지 앞다리살`(d60f539f-d3ad-4f15-ab44-27c2d7e9cf20)은 사용자 제공 100g 영양 profile이 이미 승인되어 있지만 `양념/paste_sauce`로 분류되어 있었다. 이 확인된 분류만 `육류/pork_beef_lamb`로 바로잡는다. `돼지고기 앞다리`(1ea5d6ec-5228-5022-ace8-90c648df5c03)는 별도 ID이고 영양 연결이 없다. 기존 참조와 영양 근거를 보존하기 위해 이번에는 두 ID를 강제로 합치지 않는다.

## 영양·이름·중복을 정리하는 순서

- 먼저 아래 실제 사용 30개를 정리한다. 사용하지 않는 수백 개부터 채우면 체감 개선이 작다.
- 영양 연결은 원 식품, 부위, 생것/삶음/건조 상태, 가식부, 100g 또는 1회 기준과 단위를 확인한다. 기존 승인 자료와 공공 원본의 식품 코드·버전·출처를 보존한다.
- 자료가 없는 값과 실제 0인 값을 구분한다. 비어 있는 영양을 0으로 채우거나 AI 추정값을 승인 자료처럼 저장하지 않는다.
- 이상한 이름은 원자료 이름과 실제 사용자 이름을 분리한다. 단순 속성 단어는 자동 매칭 별칭에서 제외할 후보로 검토한다. 임의로 원자료 provenance를 삭제하지 않는다.
- 의미상 중복은 대표 ID와 이전 ID의 연결표를 검토한 다음 정리한다. 레시피·팬트리·장보기·영양 snapshot 등 참조 범위를 먼저 확인하고, 과거 기록을 보존하는 이전-ID 연결 또는 비활성 정책을 사용한다.
- 유사도 검색은 오타/별칭 후보를 제안하는 용도로만 쓴다. 동물·부위·브랜드·생것/조리 상태가 다른 재료를 자동으로 합치는 근거로 사용하지 않는다.
