# 2026-10-07 재료 카탈로그 운영 정리

사용자가 전체 재료 검토 기준을 실제 DB에 반영하도록 요청했다. 집밥·일상 베이킹을 중심으로 기본 재료, 상세 상태, 음식/제품, 제외, 정의 확인을 구분한다. 영양성분과 과거 재료 ID를 보존한다.

2026-10-07 운영 반영과 사후 검증을 완료했다. 영양 연결 상태는 완전 1,482개·부분 227개·미연결 221개이며 이번 작업에서 영양값 자체는 변경하지 않았다.

## 실제 반영과 화면의 차이

새 분류는 `ingredient_catalog_groups/entries`와 일곱 공개 읽기 전용 조회에 저장한다. 기존 HTTP API/화면은 기존 재료 조회를 계속 사용하므로 화면 그룹 선택·제외 필터·대표 이름 통합에는 후속 앱 연동이 필요하다. DB의 90개 제외 분류가 기존 API의 26개 선택 제한을 자동 변경하지 않는다.

기존 105개 추가 제외/131-ID 정책 초안은 새 전수 분류로 대체했다. `archive/20261006150000_ingredient_catalog_cleanup_selection.superseded.sql`은 실행 금지 기록이다. 과거 결과 문서의 수치는 당시 이력이다.

## 보호와 검증

- 검증된 full-local 운영 DB의 전체 dump와 비밀번호 없는 역할 백업을 만들고, 네트워크·운영 볼륨 연결 없는 동일 이미지 PostgreSQL에 실제 복원했다.
- 오프라인 렌더러는 고정 입력 및 migration 원문/본문 해시를 검증한다. 스키마·분류·이름·삭제·감사·migration ledger는 한 트랜잭션으로 반영한다.
- 데이터/스키마 작업은 기존 `postgres` 권한, ledger 기록만 기존 소유자 `supabase_admin` 권한으로 수행한다. 권한 확대는 없다. 최종 ledger 해시를 행 잠금 후 재검증한다.
- 삭제 직전 전체 외래키·비FK 재료 필드·42개 JSON 열을 검사하고, 이름 변경 직전 표준명/다른 ID 별칭 충돌을 재검사한다. 삭제 원본과 변경 근거는 운영 감사 이벤트에 남긴다.
- 영양 연결·원자료·ingredient_source 프로필/성분값 및 레시피/식사/영양 snapshot 내용은 전후 체크섬으로 비교한다.
- 복원본에서 전체 취소, 참조 삭제 차단, 대표 관계 제약, 미분류 기본 노출, 공개 세 역할의 조회/쓰기 거절, 재실행 쓰기 0을 검사한다.
- 관련 테스트 3개 파일 43개 통과. UI/웹 배포·전체 빌드·전체 테스트는 이번 DB 작업 범위가 아니다.

실제 운영 확인 결과는 [결과 JSON](data/ingredient-catalog-organization-20261007-result.json)에 기록한다. 코드·문서는 작업 브랜치에 누적하며 커밋/머지/웹 배포하지 않는다.
