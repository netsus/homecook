# 로그인 없는 요리 가이드 후속

공개 레시피의 요리하기는 계정 없이 열려야 한다. 기존 snapshot_v2 상세는 비로그인 클릭을 로그인 모달로 보내고, 레시피별 공통 요리 진입 화면도 서버 세션 생성을 전제로 게스트를 막았다. 기존 공개 cook-mode GET과 과거 standalone 화면의 공개 가이드 의도는 남아 있었다.

## 수정 범위

- 비로그인 상세는 선택 인분과 복귀 URL을 유지해 공개 가이드로 이동한다. 확정된 401 또는 계정 세션/세대 stale409도 `guest=1` 가이드 URL로 이동한다. 불확실한 네트워크/서버 오류의 세션 생성은 기존 body·멱등키로 재시도한다.
- 공통 진입은 유효한 로그인 계정의 immutable snapshot session을 유지한다. 게스트는 공개 cook-mode GET을 `credentials: omit`으로 호출해 거부된 쿠키를 재전송하지 않는다. 이 옵션은 게스트 공개 GET 한정이며 기존 standalone reader의 인증 동작은 유지한다.
- 게스트 재료량은 기존 인라인 편집기를 재사용하고 분수, 단위 변환, 미확인량, 취소·포커스 복귀를 유지한다. React 상태만 갱신하며 새로고침 때 공개 원본으로 돌아간다. 공개 API에 없는 영양·무게 재계산 결과를 만들거나 계정 기록으로 표시하지 않는다.
- 게스트 완료는 화면에 종료를 표시하고 돌아가기·로그인 후 기록 시작 경로를 제공한다. 서버 요리 세션/식사 기록/팬트리 차감은 실행하지 않는다. 로그인은 로컬 편집값의 저장이나 자동 재생을 뜻하지 않으며 새 요리는 상세에서 시작한다.
- 데스크톱 상단 동작과 모바일 하단 동작은 같은 현대 요리 뷰를 사용한다. SQL, DB 구조, RLS, 인증 gateway, 소유권, 키, provider/R2 설정은 변경하지 않는다. 비공개 레시피의 공개 범위도 확대하지 않는다.

## 검증 상태

운영 Chrome에서 공개 상세의 비로그인 요리하기가 로그인 모달로 막히는 증상을 재현했다. 같은 브라우저의 로그인 프로필에서 공개 상세와 저장 상세의 실제 요리 세션 진입을 확인했다. 그 확인에서 새로 만든 세션만 취소했으며 기존 기록·재료량·팬트리·식사 기록은 변경하지 않았다.

수정 후보는 로컬 빌드와 실제 서비스의 익명 공개 recipe GET만 연결한 프록시에서 Chrome 실클릭으로 확인했다. 프록시는 인증정보와 API 쓰기를 전달하지 않는다. 1440×900/390×844에서 직접 진입, 수량 클릭, 분수·단위 변환, 저장, Escape, 새로고침 초기화, 완료, 돌아가기, 직접 URL의 선택 인분을 확인했다. 후보 서버의 DB capability는 연결하지 않았으므로 상세의 snapshot_v2 게스트 분기는 집중 UI 회귀로 확인했고 운영 반영 후 다시 실제 클릭할 대상이다. 실제 만료 계정 쿠키를 변경해 재현하지 않았으며 쿠키 제외는 API 요청 옵션 회귀와 독립 리뷰 근거다.

집중 회귀 11개 파일 245개, 전체 typecheck, 변경 파일 lint, Next 빌드가 통과했다. Anti Slop은 기존 84건·신규0이며 빌드의 기존 경고3개를 유지한다. 독립 리뷰의 stale 쿠키 P2를 수정했고 남은 P0/P1·추가 확정 P2는 없다. 현재 앱 후보이며 운영 미반영이다. PR/배포 결과는 실제 확인 후 갱신한다.
