# C01-W4 비활성 개인 무게 보정 계산 준비

상태: **합성 표본만 계산하는 순수 함수, 실제 적용·DB 읽기·수집 연결 없음**. `personal-weight-ratio-fixture-v1`의 결과는 항상 `apply=false`다. 현재 C01 실제 관찰에는 실사용량·전체음식·용기제외·섭취전·액체 경계·독립 조리의 확정 facts가 없어 적격 표본은0건이다. 화면의 ‘보고한 실측’ 문구나 저장 성공으로 facts를 true/confirmed로 만들지 않는다.

## 계산과 닫힌 조건

`lib/server/cooked-weight-personal-correction.ts`는 기존 `CookedWeightPrediction`의 고정 입력/규칙을 재검증한다. 현재 카탈로그를 읽지 않고 원예측·모델·관찰·배치·식사 수치를 수정하지 않는다. 산출 불가 예측을 개인 실측 비율로 채우지 않는다.

- 소유자와 계정 세대는 caller가 검증한 현재 subject와 정확히 같아야 한다. 이 함수는 인증을 발급하거나 DB 권한을 검사하는 adapter가 아니다.
- 같은 레시피 콘텐츠 snapshot, 안정 row key, 재료/제품과 고정 영양 정보, 원량·원단위·수량 출처(quantityOrigin)·g 환산 근거, 모델/input/catalog 판본, 생/익힘·역할·조리법·음식 경계·배수·추가 매체·프로토콜·규칙을 비교한다. 원양/규모는 exact 일치만 지원한다. 같은 숫자라도 계획량과 실제량의 조건 키를 합치지 않는다.
- 조리 조건은 근거 참조가 있는 confirmed여야 한다. 현재 inferred MIX의 가정과 unknown 준비상태를 개인 보정의 확정 조건으로 승격하지 않는다.
- 관찰은 명시 reported_measured·개인 보고·현재 active revision이어야 한다. 전체음식, 용기제외, 섭취전, 먹을 액체 포함/액체 없음, 실제 투입량 또는 고정량 준수, 독립 조리가 각각 명시 confirmed여야 한다. 모든 고정 입력 행이 planned이면 matches_pinned_quantities 확인이 필수다. reported_actual 확인은 모든 입력 행의 quantityOrigin도 reported_actual인 경우만 허용한다. unknown·계획/실제량 혼합은 행별 결속 근거가 없어 제외한다. 계획량만 있거나 일부 facts가 빠지면 제외하며, ‘실제량 보고’라는 확인 이름으로 계획량을 승격하지 않는다.
- QA·자동·단순 수동 추정·legacy·잔량·한 접시·용기 포함·섭취 후·수정 전·무효 기록은 제외한다. 같은 batch/session/observation ID 또는 독립 조리 근거 참조가 중복되면 그 그룹을 모두 제외하며 임의로 ‘최신 것’을 고르지 않는다. 실제 adapter는 해당 조리 근거가 진짜 고유 batch/session과 결속됐는지 확인해야 한다.

조건이 같은 적격 독립 batch가 최소3개일 때 기존 예측 대비 실측 비율의 중앙값을 계산한다. 미래 대상의 같은 조건 예측에 그 비율을 곱한 **fixture 후보 숫자**만 반환한다. 3개는 v9의 초기 최소 검토 기준이며 정확도·신뢰확률·실제 품질 보증이 아니다. 화면·영양·원기록에 연결하지 않는다.

입력 규모가 조금만 달라도 외삽을 거부한다. 검증된 ‘가까운 규모’ 범위나 선형 증발 가정을 새로 정하지 않았다. 확인한 전체 투입 g를 넘는 관찰/후보도 보수적으로 제외한다. 환산 근거가 추정인 경우 이 상한은 실제 물리 측정을 보증하지 않으므로, 적격 실제 사용량/환산 불확실성 정책 검증 없이 운영에 적용하지 않는다.

## 품질·개인/집계 분리

비율 최소/최대와 중앙값 기준 상대편차 허용치는 기본값이 없다. 명명된 `synthetic_fixture` 정책과 검증 근거 참조가 명시되지 않으면 계산을 닫는다. 테스트의 숫자는 합성 산술 검사용이며 실제 기간·허용 오차·운영 품질을 승인한 값이 아니다. 극단값의 원 관찰은 유지하고 이 계산의 적격 여부만 제한한다.

이 함수에는 C05 참여 상태·동의·사용자 집계 입력이 없다. 개인 실측 저장과 개인 미래 보정은 전체 모델 참여 여부와 분리된다. 현재 결과는 비활성 fixture이므로 ‘참여하지 않은 사용자에게 실제 개인 보정이 이미 제공된다’는 뜻도 아니다. 전체 모델용 복제·수집·외부 전송·모델 훈련은0이다.

보유기간·자료나이의 유용성·삭제·탈퇴·정정/무효화 전파는 이 메모리 계산으로 구현하지 않는다. 기간을 무기한 또는90일/1년으로 확정하지 않았고, 실제 adapter에는 원기록 정책·현재 subject·원 revision·삭제/무효 상태를 다시 검증하는 경계와 품질 정책이 필요하다. 지금 이력이 오래됐다는 이유로 유용하다고 추정하지 않는다.

## 미연결·후속 경계

실제 C01 DB에는 필요한 측정 facts가 없다. 이번 함수는 DB 스키마·API·질문/수량 입력 UI·collector·완료/weight RPC·기존50파일을 바꾸지 않는다. 문자열을 facts로 해석하거나 현재 기록을 임의 복제해 채우는 adapter도 없다.

운영 개인 보정 연결 전에 실제 facts 저장/검증, 정정·삭제·계정세대 전파, 같은 조건과 규모의 적격 표본, 자료나이/오차 평가, 독립 품질과 적용/중단 기준을 별도로 확정해야 한다. 현재 모델과 새 모델·단위 판본을 섞지 않고 과거 예측/식사 근거를 보존해야 한다. C04의 원량/분수/당시 인분 계약과 C03 실제 통합은 기존 담당/root가 후속 연결한다.

검사는 새 전용 unit test와 기존 순수 예측 검사를 함께 선택한다. 좁은 TypeScript 검사는 새 source/test와 실제 import되는 타입/순수 함수를 검사하며, C03 통합 전 전체 프로젝트 typecheck/build를 대신하지 않는다. lint·Anti Slop·파일 manifest를 인계 기록에 고정한다.
