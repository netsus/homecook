# 직접 등록·모바일 입력 개선

2026-09-27 피드백 누적 브랜치. 운영 데이터 변경·머지·배포는 이 작업에 포함하지 않는다.

## 등록과 공개 범위

- 직접 작성한 원본은 공개 검색·공유 대상이다. 기존 레시피에서 만든 개인 사본은 비공개를 유지한다. `source_type=manual`만으로 둘을 동일하게 취급하지 않는다.
- 공개할 직접 등록 원본은 현재 사용자 소유, `origin_recipe_id IS NULL`, 직접 등록의 검증된 저장 영수증을 확인한다. 요청 JSON의 임의 visibility로 공개 권한을 얻을 수 없다.
- 직접 등록 화면에 공개·검색·공유되는 사실을 안내한다. 공개된 원본도 작성자만 편집·삭제할 수 있고, 다른 사용자는 개인 사본만 만들 수 있다.
- 관리 사진은 비공개 원본에서 검증된 공개 사본으로 복사한다. 원본의 private 경로나 signed URL을 공개하지 않는다. 같은 요청은 같은 이미지 대상으로 재시도한다.
- 공개 Storage 쓰기 전에 이미지 registry/연결, 공개 의도, 영양 정보와 조리 내용 고정본, 저장 영수증을 DB에서 함께 확정한다. 그 뒤 공개 사진 바이트를 검증하고 ready를 확인해야 등록 성공을 반환한다. 중간 공개 레시피는 사진 대신 중립 placeholder를 보일 수 있으며, 실패하면 영속 journal과 같은 요청으로 복구한다. 계정/원본 삭제로 pending 추적이 사라지지 않고, 오류 시 다른 요청의 성공 사진을 삭제하는 보상은 실행하지 않는다. 상세 계약은 [이미지 공개 경계](../security/manual-recipe-publication-boundary.md)를 따른다.
- 이미 직접 등록한 비공개 원본에는 소유자가 누를 수 있는 ‘공개하여 검색·공유하기’를 제공한다. 서버는 현재 계정 세대의 실제 직접 등록 영수증을 확인한다. 출처가 불명확한 legacy 데이터나 개인 포크를 일괄 공개하지 않으며 GET에는 공개 부작용이 없다.
- 공개 공유 링크에는 이전 작업 화면이나 개인 레시피북의 returnTo를 넣지 않는다. 개인 사본은 다른 사람이 열 수 없는 링크를 공유했다고 안내하지 않는다.

## 모바일 작성 흐름

- 뒤로가기/이탈 감지는 입력마다 등록 해제·재등록하지 않는다. 최신 이동 callback은 ref로 유지하며, 한글 조합 중 Escape를 닫기 신호로 해석하지 않는다.
- 재료 추가 모달은 가용 화면 높이를 사용한다. 검색창·선택 상태·추가 버튼을 고정하고 결과 목록만 세로 스크롤한다. 검색 전후 결과 수가 바뀌어도 검색창 위치가 이동하지 않는다.
- 모바일에서는 모달을 열자마자 검색창으로 자동 포커스하지 않는다. 사용자가 입력창을 선택하면 입력하며 글자 크기는 최소 16px다. 확대 접근성 자체를 차단하지 않는다.
- 직접 등록의 만들기 추가 버튼까지 하단 탭·안전 영역 위로 스크롤할 수 있도록 높이와 여백을 맞춘다.

## 숫자와 조리 방법

- 숫자는 편집 중인 문자열과 저장할 숫자를 구분한다. 빈 값·`12.` 같은 중간 입력을 즉시 0으로 바꾸지 않는다. 저장할 때 기존 수량·무게의 유효 범위와 필수값을 확인한다.
- 재료·개인 편집·YouTube 편집·식사 기록의 해당 입력에 공통 DecimalInput을 사용한다. 이미 문자열 초안을 사용하던 입력은 불필요하게 교체하지 않는다.
- 조리 방법은 기존 taxonomy에서 명확한 한 가지 동작이 확인될 때만 자동 선택한다. 부정문·대안·복수 동작은 추측하지 않는다. 사용자가 선택한 값은 유지하고 자동 선택했던 값은 문장 변경에 따라 갱신한다.

## 영양과 바로 요리

직접 등록이라는 이유로 영양 계산을 제외하지 않는다. 등록 후 영양 쓰기 실패를 성공으로 삼키던 경로와 바로 요리하기에 필요한 내용 고정본 누락을 바로잡는다. 영양 데이터가 없는 재료는 기존 미계산·부분 계산 계약을 유지하며 임의 0이나 추정값으로 성공을 만들지 않는다.

## 검증 범위

변경된 흐름의 회귀와 모바일 375px·데스크톱, 키보드가 공간을 차지하는 짧은 화면을 확인한다. DB·이미지 공개 상태 전이는 폐기 가능한 격리 환경으로 확인한다. 실제 iPhone 소프트 키보드 및 운영 Storage 연결은 아직 검증하지 않았다. 전체 테스트·배포·백업 복원을 개별 수정마다 반복하지 않는다.


## 확인 결과

- 375px·데스크톱 직접 등록에서 한글 조합/이탈 확인창, 만들기 추가 버튼, 조리 방법 자동 선택·수동 우선 확인.
- 재료 모달 375×812/375×420/데스크톱에서 검색창 위치 변화 없음, 결과 단일 스크롤, 16px 입력과 닫기 포커스 복원 확인.
- 숫자 입력 관련 79개 선택 회귀 및 모바일·데스크톱 입력 확인. 빈 값·소수 작성 중 상태·기존 최소/최대값을 보존한다.
- 기존 직접 등록 명시적 공개의 API 권한 6개, UI 3개, 모바일 2개 확인. 개인 사본에는 공개 버튼이 없고 준비/실패 상태에 성공 안내가 나오지 않는다.
- 최초 POST 준비 미완료 → 조회 준비 미완료 → 동일 키·본문 POST 재시도 후 단일 성공을 확인했다. 인증·네트워크 조회 실패 때는 POST 재전송을 막는다.
- 120400/120500/120501/120600을 함께 적용한 격리 DB에서 직접 생성 → 기존 private 계획 → 공개 영양/내용 → 즉시 요리 → private fork → 공개 원본 재편집 → 기존 계획 유지 → 원본 삭제 후 기존 계획 장보기까지 확인하고 롤백했다.
- 이미지 공개 copy/hash/권한/상태·runtime rollback과 재시도는 격리 테스트로 확인했다. 운영 Storage를 실제로 변경하지 않았다.
- 전체 과거 UI 테스트 중 이미지 업로드·옛 화면 진입/문구를 전제로 한 실패는 이번 수정 범위에서 정비하지 않았다. 변경 흐름의 선택 회귀 결과와 전체 테스트 성공을 혼동하지 않는다.
