# 로컬 확인과 테스트

## 상태

출시 전 개발 단계에서는 CI와 자동 QA gate를 사용하지 않는다. 개발자가 로컬 앱을 직접 사용하면서 기능을 확인하고 수정한다.

## 기본 확인 순서

1. `pnpm dev` 또는 필요한 로컬 실행 환경을 시작한다.
2. 변경한 흐름을 모바일과 데스크톱에서 직접 실행한다.
3. 정상 상태뿐 아니라 로딩, 빈 결과, 오류, 권한 없음과 read-only 상태를 확인한다.
4. 발견한 문제를 고친 뒤 같은 흐름을 다시 확인한다.
5. 배포 전 `pnpm typecheck`와 `pnpm build`를 권장한다.

## 테스트 선택

- 관련 Vitest: 바꾼 로직의 회귀 위험이 있을 때 실행한다.
- Playwright smoke: 여러 화면을 잇는 핵심 흐름을 바꿨을 때 실행한다.
- 접근성·화면 비교·Lighthouse: 큰 UI 변경이나 출시 준비 때 실행한다.
- 전체 테스트: 여러 영역을 건드린 변경이나 출시 후보를 확인할 때 실행한다.

테스트 보고서, screenshot evidence, QA eval, authority report는 일반 PR의 필수 산출물이 아니다.

## 반드시 자동화된 확인을 남길 영역

화면을 눈으로 보는 것만으로 확인하기 어려운 다음 영역은 관련 테스트를 유지한다.

- 인증과 session
- 다른 사용자 리소스 접근 차단
- 상태 전이와 멱등성
- 완료 후 read-only
- migration과 RLS
- 백업·복원·배포 실패 처리

## 출시 준비

고객 유입 또는 광고 집행 전에는 핵심 사용자 흐름의 짧은 Playwright smoke와 typecheck/build/관련 테스트를 CI로 다시 연결한다.
