## 누락을 만들던 원자료 해석 보완

공식 RDA10.4 workbook 「DB 설명」의 3절에서 괄호 숫자는 인용되었거나 재료량으로 환산한 수치임을 확인했다. 기존 변환기는 `(0)`, `(88.2)`를 잘못된 숫자로 간주해 행 전체를 격리했다.

이번 수정은 **농촌진흥청·정확한 dataset·버전10.4·기존 고정 원본 SHA256이 모두 일치할 때만** 해당 표기를 처리한다. 원문 `source_token`과 `cited_or_converted` 성격을 보존하고, DB에는 원자료 항목의 `provenance_json.rda_qualified_nutrients`에 함께 저장했다. `-`는 결측, `Tr`와 `(Tr)`는 미량/null이며 임의 수치를 생성하지 않는다. 일반 숫자와 다른 공급자의 해석 규칙은 유지한다.

공식 전체3366행 비교 결과:

- 이전3206행 정상·160행 격리 → 이후3366행 해석 가능·격리0.
- 기존3206행의 fingerprint와 content hash는 모두 같다.
- 새로 해석 가능한160행의239개 인용/환산 표기를 보존했다.
- **전체3366행을 DB에 적재하거나 승인한 것은 아니다.** 이번에 실제 반영한 것은 개별 검토119개 연결이다. 그 안에 포함된 괄호 표기31개를 DB 원문·출처까지 확인했다.
- 신선초의 Excel 표현 `2.8000000000000003`은 DB `numeric(14,6)`에 맞춰 입력 amount만2.8로 표현했다. 원문 토큰·원본 해시는 보존하고 일반 변환기의 반올림 계약은 바꾸지 않았다.

드라이이스트·파슬리가루·황태채는 검토한 일반 건조 식품의 대표 자료다. 특정 브랜드 제품을 직접 분석한 값으로 표시하지 않는다. 말린 제빵 효모의 동일성은 [일본 공식 식품성분 자료17083](https://fooddb.mext.go.jp/details/details.pl?ITEM_NO=17_17083_7&MODE=7)도 대조했다.

## 검증과 실행 경계

- 변경 직전 소유자 전용 DB 전체 백업116,640,398bytes를 새로 만들고 운영 포트·볼륨을 공유하지 않는 네트워크 격리 PostgreSQL에 실제 복원했다. Cloud/linked DB 접근은 없다.
- 복제본에서 이전 링크 변경 감지, 후반 별칭 오류 시 전체 취소, 기존 품질 보류 자료의 재승인 차단,119개 연결·2개 철회·19개 별칭 제거를 검증했다.
- 운영에서119×8=952개 영양값·원문 토큰·결측/미량을 대조했고 인용/환산31개를 보존했다. 재실행의 추가 변경0, snapshot 추가0을 확인했다.
- 재료·레시피·재료행·계획·식사·내용 고정 기록의 전후 checksum은 같다. 실제 삭제0건이다.
- 관련6개 테스트 파일 **147검사 통과**. 후보 매칭에서는 초코칩→쿠키를 추가 차단하면서 정상 쿠키·비스킷 후보를 유지한다.
- 외부 음식 조회 HTTP 확인은 비로그인403으로 응답했다(18:25 KST). 로그인한 실제 UI 확인은 완료하지 않았다. 서비스가 정상이라고 주장하거나 인증·네트워크 설정을 변경하지 않는다.

실행 결과·백업 checksum·원자료 전체 비교·남은 건수는 [검증 결과](data/ingredient-nutrition-curation-20261006-followup-result.json), 고정 입력은 [반영 JSON](data/ingredient-nutrition-curation-20261006-followup.json)에 있다.
