## 대상과 복구 준비

- 기존 full-local 운영 설정으로 컨테이너·볼륨·이미지·DB 대상이 일치하는지 확인했다. Supabase Cloud 또는 linked remote DB를 사용하지 않았다.
- 변경 전에 DB/Auth/Storage 전체 암호화 백업, 인증된 별도 장치 복사, 격리 환경의 실제 복원과 escrow 복구를 완료했다. DB/Auth 의미 해시와 Storage 1개 객체의 내용·참조가 일치했다.
- 백업 readiness 경로를 새 검증 결과로 갱신했다. 실제 시작 도구가 사용하는 resume inventory도 이전 파일을 보존하고 원자적으로 재봉인했다. `--check-only`에서 서비스 7개, 시작·중지 0건이었다. 기존 자원·이미지·네트워크·환경 바인딩은 동일했다.
- 비공개 실행 증거는 저장소 밖 `~/.homecook/operations/beta-rollout-20260922-ACzBhd/`에 보관한다. 자격증명·계정 식별자·사용자 기록은 이 문서에 복사하지 않는다.

## 기존 계획 1건 보완

내용 고정 데이터가 없던 미완료 계획 1건을 기존 backfill 함수로 보완했다. 대상 전체 집합이 정확히 그 1건인지, 행의 기존 값과 실행 전후 상태가 일치하는지 잠금 안에서 검사하고 먼저 rollback 검증을 수행했다.

- 내용 snapshot 1개 추가, 해당 계획 revision 1 증가, 누락된 계획 pin 0건.
- 날짜·상태·인분·장보기 연결은 보존했다. 다른 계획, 기존 내용 snapshot, 기존 영양 snapshot은 변경하지 않았다.
- 당시 영양 고정 값의 `NULL`은 그대로 보존했다. **이번에 확인한 현재 레시피 내용을 `legacy_backfill`로 고정한 것이며, 알 수 없는 과거 원문이나 영양을 복원했다고 표현하지 않는다.**

## 설정 활성화와 운영 도구 수정

- 두 DB 기본 설정을 같은 트랜잭션에서 `on/on`으로 바꿨다. 새 연결에서 `snapshot_v2`, 계정 세대 `generation_active`, 누락/불일치 계획 pin 0, 역할별 override 0을 확인했다.
- 실제 설정 반영을 위해 확인한 기존 PostgREST 컨테이너만 재시작했다. ID·이미지·환경은 유지했으며 앱의 레시피 API는 HTTP 200으로 응답했다. 웹 빠른 배포와 별도의 명시적 운영 조치다.
- Docker가 같은 mount 목록을 다른 순서로 반환해 대상 변경으로 잘못 판단하던 문제를 수정했다. 전체 필드와 중복은 보존하고 순서만 정규화한다.
- 일반 `postgres` 역할은 보호된 설정을 변경할 수 없었다. 기존 관리 역할 `supabase_admin`의 권한을 검사한 뒤 설정 트랜잭션에만 사용하도록 수정했다. 일반 조회·사전 검사·새 연결 확인은 기존 역할을 사용하며 새 권한을 부여하지 않는다.
- 미등록 과거 이미지 1건은 경고로 남겨 두었다. 잘못된 private 이미지 참조는 0건이며 이미지를 자동 삭제하지 않았다.

CLI의 `activation_verified:false`는 앱 검증까지 자동 수행했다는 의미로 바꾸지 않는다. 실제 화면 결과와 그 한계는 아래에 별도 기록한다.

## 실제 화면 확인과 남은 확인

실제 운영 브라우저에서 새 편집 버튼 노출과 독립 요리 세션 생성을 확인한 뒤, 공개 레시피 편집과 요리 기록 조회 오류를 발견했다. 적용 이력만 확인했던 범위를 실제 함수 정의·권한·DB 로그 및 전체 migration 격리 재생 결과 비교로 넓혔다.

- 공개 레시피 편집 context와 개인 레시피 writer가 8월 후속 변경 전 본문으로 남아 있었다. 원본 revision 검사, 복사 출처·태그, 제품 버전 쌍을 포함한 최신 정의로 복구한다.
- 요리 조회 함수의 `STABLE` 선언 때문에 PostgREST가 읽기 전용 트랜잭션을 사용했고, 내부 권한 검사에 필요한 `SELECT FOR SHARE`가 실패했다. 권한 검사와 잠금을 제거하지 않고 `VOLATILE` 선언으로 수정한다. 운영에서 이미 보완된 남은요리·식사 조회의 같은 선언은 유지한다.
- 내부 영양 입력 guard에 남은 익명·사용자·service 역할의 직접 실행 권한은 최신 계약의 소유자 전용 권한으로 회수한다. 역할·환경 차이를 일괄 덮어쓰지 않는다.

위 추가 복구는 `20260922030000_recipe_snapshot_activation_repairs.sql`로 남겼으며, 관측된 이전 정의 또는 검증한 최신 정의에만 적용한다. 운영 rollback 검증 후 **2026-09-22 18:40 KST 확정 적용**했다. 기존 기록 6종의 내용 해시는 동일하고 ledger는 **183개**다. 최종 SQL SHA는 `3d1413ac15ee61d2e974e9c0783eb81c9af5a488f3ac0b149dd980b59e29758c`다.
