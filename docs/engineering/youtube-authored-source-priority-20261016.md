# 설명란·작성자 댓글의 명시 수량 우선 — 2026-10-16

## 범위와 상태

사용자는 설명란과 작성자 댓글에 있는 명시 재료·수량을 먼저 보존하고, 부족한 항목만 자막·영상으로 보완하도록 요청했다. 독립 브랜치 `codex/youtube-authored-source-priority-20261016`에서 수정했다. 후보는 client v72 / verifier v45이며, 운영 v71·worker·DB·배포는 변경하지 않았다. 이 작업의 모델·영상·네트워크 provider 호출은 0회다.

평가가 확인한 설치 릴리스는 `6b610eb012da42b5d151b058531815dc12a8ca45`다. 당시의 원시 응답·검증 trace·정답지는 그대로 보존하며, 이번 결과는 **동일 응답의 오프라인 재생**이다. 새 추출 점수나 전체 P5 통과 판정으로 취급하지 않는다.

## 원인 확인

세 trace를 수정 전 master verifier로 재생해 저장된 결과와 전체 객체가 일치함을 확인했다. 대표 사례는 다음과 같다.

| 사례 | 모델 원시 값 → 기존 검증 후 값 | 기존 거절 사유 | 확인한 원인과 구분 |
| --- | --- | --- | --- |
| 낙지볶음 설탕 | `5 / 스푼` → `null / null` | `qualified-quantity-not-atomic` | `설탕 5스푼 50g`의 두 번째 병기량을 변경·추가량으로 오인했다. 파서의 false negative다. 같은 입력의 구분자만 `5스푼 \| 50g`으로 바꾼 메모리 내 probe는 원본 검증기로 통과했다. |
| 양파 영상 물 | `70 / ml` → `null / null` | `quantity-not-bound-to-name` | `물 _________ 70ml`에서 밑줄이 수량 앞에 남고, source binding의 재료명도 `물 _________`가 됐다. 목록 구분자 처리 버그다. 밑줄만 제거한 메모리 내 probe는 통과했다. |
| 소갈비찜 감자 | `두 / 개` → `null / null` | `literal-repair-role-ambiguous` | 한 자막의 `물을 넣어가면서 끓여 줘 감자 두 개`에서 후반 재료 절을 직접 결속하지 못하고, caption/OCR 두 역할이 복구 단계의 단일 역할 조건에 걸렸다. 숫자가 없는 것이 아니라 현재 문법·역할 보호의 보수적 제한이다. OCR 인용만 제거해도 복구되지 않았으며, 원문을 단독 `감자 두 개` 절로 제한한 probe에서만 통과했다. 역할 보호 자체는 이번에 완화하지 않았다. |

기존 코드 위치는 `source-anchored-vision.mjs`의 `readPairs`, `bindings` 내 `changedAmount/compound`, `literalRepairScope`, explicit 수량의 `eligible` 검사다. owner 이름 경계는 `source-quantity-owner-hints.mjs`의 `cleanBindingName`이다. 최종 null은 이 검증 결과를 그대로 보존한 것이며 DB 저장 과정에서 지워진 것이 아니다.

## 변경

- 닫힌 `숟가락/개수 단위 + 명시 g/mL` 병기를 같은 원문의 primary/reference로 읽는다. 원문에 없는 환산율을 계산하지 않으며 `+`, 부분 사용, 범위·근사 보호를 유지한다.
- 두 개 이상 밑줄로 된 목록 리더를 이름·수량 구분자로 읽는다. 원문과 수량 좌표는 바꾸지 않는다.
- 서버가 이미 소유자를 결속한 닫힌 설명란/작성자 목록 행에서는 모델의 explicit 수량 재서술보다 원문 수량을 우선한다. 모델이 선택한 원문 reference 중량도 그대로 허용한다. unknown/review 사례에는 기존의 더 좁은 복구 정책을 유지한다.
- 누락 행 추가는 같은 원문 그룹에 현재 레시피의 서로 다른 재료 두 개 이상이 있고, 유일한 owner가 있으며, 조건·부정·광고·충돌이 없을 때만 한다. 다른 요리 제목의 그룹은 제외한다. `큰거/큰 것/작은거/작은 것`이 붙은 원문 owner를 모델이 직접 인용했고 모델의 중량이 그 owner의 명시 reference와 일치하면 원문 이름을 originalName에 보존해 같은 행을 결속한다. 그 외 수식어가 기존 행과 겹치면 별도 재료를 추가하거나 동일 재료라고 단정하지 않는다.
- 실제 설명란/댓글/결속 가능한 자막 수량 충돌은 `conflicting`과 양쪽 원문 근거로 남긴다. 평균하지 않는다. 약간이나 미기재를 5g 같은 숫자로 바꾸지 않는다.
- 공식 snapshot 수집기의 작성자 댓글 선택을 순수 함수로 분리했다. 영상의 유효한 채널 ID와 `authorChannelId`가 일치할 때만 선택하고, 선택한 ID도 보존한다. 일반 시청자·작성자 미식별 댓글은 제외한다. `author_comment` marker는 이 서버 필터를 지난 입력용이며 일반 댓글 marker는 ledger source가 아니다.
- 후보 identity와 번들 manifest 해시를 갱신했다. 프롬프트 튜닝·공개 API·DB 계약 변경은 없다.

## 검증

- 관련 Vitest 4개 파일: **295개 통과**, 실패·건너뜀 0. `youtube-authored-source-priority`, `youtube-source-bound-quantity-recovery`, `recipe-loop-local-integrity`, `youtube-i031-runtime`를 실행했다.
- `COREPACK_ENABLE_NETWORK=0 corepack pnpm verify:anti-slop`: 통과, 신규 위반 0. 기존 baseline을 늘리지 않았다.
- 선택 ESLint: 오류 0, 기존 `_private` 미사용 경고 1. 공유된 기존 의존성의 plugin 탐색에 `NODE_PATH`를 사용했으며 의존성을 추가하지 않았다.
- `git diff --check`: 통과. 운영 검증·전체 테스트·앱 typecheck/build·신규 추출은 이 범위에서 실행하지 않았다.

새 회귀 검사는 설명란 우선, 작성자 댓글 우선, 모델 재서술 복구, 같은 목록의 누락 행, 자막 보완, 실제 충돌, 일반 시청자 제외, 무관한 요리·광고 숫자 제외, 모호량 비수치화, 부분 사용 보호, 기존 수량 유지와 수식어 중복 방지를 다룬다.

### 커밋 전 별도 diff 검토

작성자 신뢰 경계, 설명란·댓글 충돌, 잘못된 숫자 유입을 다시 검토했다. 작성자 ID가 없는 댓글과 시청자 댓글은 배제되고, 기존 수집기 외에 댓글을 신뢰하는 새 공개 입력 경로는 추가하지 않았다.

검토 중 두 경계를 수정했다. 설명란의 `설탕 5스푼 50g`과 작성자 댓글의 `설탕 60g`은 primary뿐 아니라 reference 중량까지 비교해 양쪽 원문을 가진 충돌로 남긴다. 다른 요리·광고의 명시 제목 뒤 자막은 새로운 cross-source 충돌 검사에서 제외한다. 표적 회귀 3개를 추가했고 최종 관련 검사 295개가 통과했다. manifest 갱신 전 1회 실행에서는 번들 해시 검사가 실패했으며, 후보 해시를 동기화한 후 4개 파일 모두 통과했다.

최종 코드로 원시 trace 3개를 다시 재생해 이전 오프라인 결과 전체 객체와 동일함을 확인했다. 정답지 해시와 번들 22개 해시도 다시 대조했다. 해결하지 않은 새 차단 사항은 없다. 자동 채점 결과의 실제 운영 개선은 배포와 별도 승인된 추출 전에는 확인할 수 없다.

### '21개' 집계와 기존 응답 재생

사전 고정 정답의 숫자·단위 허용쌍과 모델 원시 수량이 일치하고, 기존 post-verifier의 amount/unit가 **둘 다 null**인 재료 행만 센다. 미림의 세척용·양념용은 별도 행이다. 약간, 가래떡의 미확정량, 밀가루의 estimated 표현, 식용유 충돌, 진간장 90mL 보류, 다진 마늘 재료 누락은 21개에 포함하지 않는다.

| 영상 | 기존 소실 | 이번 재생에서 복구 | 남음 |
| --- | ---: | ---: | ---: |
| 낙지볶음 | 10 | 10 | 0 |
| 양파순두부덮밥 | 6 | 6 | 0 |
| 순살소갈비찜 | 5 | 0 | 자막 절/역할 결속 5 |
| 합계 | 21 | 16 | 5 |

기존 non-null 수량 10개는 값·단위가 모두 유지됐다. 재료 행 수도 그대로이며 대파 수식어를 별도 재료로 중복 추가하지 않는다. 재생 입력 SHA-256을 원본 freeze와 대조했고, [행별 재생 증거](evidence/youtube-authored-source-priority-20261016-replay.json)에 기록했다. 정답지 SHA-256은 `848c29e69fba85ce2a34b08b6bc9c9b6b39f0e2ef309818f2894e8b50975f7b4`로 유지했다.

남은 자막의 공유·후행 재료 절은 별도의 소유권 문법 검토가 필요하다. 이번 수정에서 단일 역할 보호를 끄거나 명칭을 임의 치환하지 않았다. 설명란·댓글에만 있는 명시 항목의 보존이 개선됐다는 증거이며 모든 21개 또는 모든 영상의 추출 문제가 해결됐다는 의미는 아니다.
