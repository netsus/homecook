cv-goal-i031-ocr 실험환경을 localhost 서비스에 그대로 연결하는 계획

현재 최선 iter를 고른 근거, 완료된 exact 환경 복구, 임의 YouTube URL 테스트, 출시와 롤백 기준을 초보 개발자 눈높이로 정리했습니다.

!딱 한 줄 요약

Gemini나 최신 OCR 코드를 붙이는 일이 아닙니다. 당시 i031의 source 수집, 프레임 선택, 두 번의 Codex 모델 호출에 쓰인 exact 파일과 옵션은 이미 복구했습니다. 이제 그 production subset을 서비스 내부에서 직접 실행하게 만듭니다.

동일 fingerprint와 실행 signature, exact CLI를 확인했고 fresh Validation은 PASS했습니다. Fresh Train은 단계 점수 문턱에 미달했으므로 localhost 검증과 production 승인을 분리합니다.

1가장 먼저 구분할 것

이번 목표: 100% strict parity

  • 당시 source provider와 fallback 순서 유지
  • client/prompt/model/frame 옵션 exact match
  • cold, no-cache 실행
  • identity가 다르면 결과 저장 금지

이번 범위가 아닌 compatible mode

  • yt-dlp만으로 모든 source 대체
  • 현재 최신 experiment client 호출
  • macOS Vision OCR 추가
  • Gemini로 실패를 자동 보완
중요한 정정 i031의 OCR은 macOS Vision census가 아닙니다. gpt-5.4-mini selector가 최대 12개 frame을 보고 화면 글자와 수량 cue를 읽은 동작입니다.

4복구된 것과 아직 배포할 수 없는 이유

복구 완료: exact code Candidate lock commit에 없던 client v19, final prompt v44, 실행 command를 session history에서 복구해 fingerprint를 exact match했습니다.

8단계별 구현 순서

  • 0

    Exact runtime 복구 · 완료

    v19/v44 bytes, fingerprint, signature, CLI와 숨은 옵션을 exact match했습니다.

  • 1

    Train·Validation 재실행 · 완료

    Cold/no-cache로 실행해 Validation PASS와 Train step threshold FAIL을 모두 기록했습니다.

  • 2

    공식 문서와 workpack · 진행 중

    Localhost strict mode, 기존 오류 wrapper, 안전한 DB metadata를 이 contract-evolution에 반영합니다. 비동기 status는 후속 범위입니다.

  • 3

    Runner·adapter TDD

    먼저 실패/identity mismatch 테스트를 쓰고 service worker contract를 구현합니다. 예상 1~2일.

  • 4

    localhost 연결

    기존 YT_IMPORT에서 임의 링크를 넣고 진행 상태와 검수 화면까지 확인합니다. 예상 0.5~1일.

  • 5

    Production worker hardening

    Queue, timeout, cancel, secret, rate limit, 로그를 완성합니다. 예상 1~2일.

  • 6

    Holdout·단계적 출시

    fresh sealed Holdout PASS 뒤 localhost → 내부 → 5% → 25% → 전체 순으로 넓힙니다. 예상 0.5~1일.

복구와 재검증은 끝났습니다. Localhost 구현의 남은 예상은 2.5~4일이며 production worker와 Holdout은 별도 승인 범위입니다.

10실패 처리와 안전 규칙

허용

  • Network 일시 오류 1회 재시도
  • 공개 caption 실패 시 당시 조건의 Apify 1회 fallback
  • DB 저장만 멱등 key로 재시도
  • 사용자가 직접 기존 모드 재시도 선택

금지

  • Selector/final model 자동 교체
  • Gemini 자동 fallback
  • Identity mismatch 결과 저장
  • 특정 video ID별 정답 분기
Source 수집 실패

어느 단계에서 실패했는지 보여주고 strict run을 종료합니다.

Codex 로그아웃·timeout

프로세스를 종료하고 recipe draft를 저장하지 않습니다.

미등록 재료

unresolved 또는 needs_review로 내려 사용자 확인을 받습니다.

누수 위험

서비스 runtime에는 source 처리 코드만 포함하고 golden·grade·review 파일을 넣지 않습니다.

비용 급증

동시 실행 1, 대기열 3, 사용자/일일 quota로 시작합니다.

긴 처리 시간

단계 상태와 취소 기능을 제공하고 production은 queue worker로 분리합니다.

11localhost에서 임의 링크 테스트

  1. 서비스 내부 i031 runtime fingerprint 검증 command가 PASS인지 확인합니다.
  2. Codex CLI 로그인, Python 3, yt_dlp, OpenCV/FFmpeg를 확인합니다.
  3. .env.local에 Supabase 값, YouTube key, 조건부 Apify token, i031 mode를 넣습니다.
  4. pnpm dev로 서비스를 켭니다.
  5. http://localhost:3000/menu/add/youtube에 접속합니다.
  6. 임의의 공개 단일 레시피 URL을 입력합니다.
  7. source → frame → selector → final → mapping 진행 상태를 봅니다.
  8. 검수 화면에서 제목, 재료, 수량, 단계, review-required를 확인합니다.
  9. Result identity가 i031 고정값과 같은지 확인합니다.
YOUTUBE_RECIPE_EXTRACTOR_MODE=i031_codex_vision
YOUTUBE_API_KEY=server-only
APIFY_TOKEN=server-only
최소 real-link 세트 설명란이 풍부한 영상 1개, Apify caption fallback이 필요한 영상 1개, 화면 글자가 중요한 영상 1개를 테스트합니다.

12공식 문서와 승인 순서

사용자 결정 · 완료“실험환경 100% 동일”을 contract-evolution의 방향 승인으로 기록했습니다.
Contract evolution · 이 PR에서 완료Strict mode, 기존 error wrapper, 안전한 DB metadata, localhost-only 경계를 공식 API/DB/User Flow 문서에 반영했습니다.
Codex Stage 1 독립 검토새 workpack, acceptance, automation spec, workflow item을 별도 Codex critic이 검토하고 PASS하면 main에 merge합니다.
그 다음 구현이 Stage 1 PR이 merge된 뒤 서비스 내부 i031 runtime 구현을 시작합니다.

이 PR 자체가 localhost 구현에 필요한 contract-evolution입니다. i031 strict mode는 기존 public endpoint와 화면을 유지하며 동기 실행으로 시작합니다. Production queue와 async job status는 별도 승인 전 구현하지 않습니다.
