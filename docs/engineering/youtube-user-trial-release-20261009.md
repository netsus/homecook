# 유튜브 레시피 사용자 시험 배포 — 2026-10-09

## 사용자 결정과 범위

사용자는 정식 P5 성능 평가를 기다리지 않고 먼저 배포해 직접 사용하면서 개선을 이어가기로 했다. 이는 이번 사용자 시험 배포의 순서 변경이며, 기존 시험 점수를 변경하거나 P5 합격으로 처리하는 결정은 아니다.

배포 대상은 Codex Vision 기반 Luna low 추출기와 자동 저장된 개인 레시피 화면이다. 추출 결과를 서버에서 소유자별로 보관한 뒤 저장된 상세로 이동한다. 최초 저장 버튼 없이 읽고, 실제 수정에만 변경사항 저장을 제공한다. 개인 결과를 정규 공개 레시피·식단·장보기로 자동 승격하지 않는다.

## 확인한 통합

- source-anchored v63, verifier37, 원문 우선 질문17, schema3, 선택 이미지8개, 로컬 프레임 생성 작업4개를 사용한다.
- 소유자 정보가 없는 기존 전역 결과 캐시의 읽기와 쓰기를 모두 끈다. 소유자별 기존 작업·저장 결과의 재조회는 별도 권한 계약을 유지한다.
- 실제 비동기 워커 RPC까지 수량 상태·출처를 전달한다. 미확인·충돌을 취향껏으로 바꾸지 않는다. 이미지 추정과 화면에 적힌 문자를 구분하며, 추정값은 확정값으로 저장하지 않는다.
- 원래 사용자 편집본을 반복 추출 진입이나 새로고침으로 덮어쓰지 않는다.
- 기존 운영 SQL207개를 유지하고 자동 저장, 비동기 수량 변환, 카탈로그 검증값 갱신의 세 SQL만 추가하는 210개 경로를 검증했다.

## 실제 사용 중 발견하고 고친 문제

1. 자동 실행 시 Homebrew Python이 먼저 선택되어 영상 모듈을 찾지 못했다. 시스템 Python 우선 PATH로 해결했다.
2. macOS 임시 폴더 `/tmp`와 실제 경로 `/private/tmp` 차이로 worker 진입점 검사가 실패했다. 운영은 canonical TMPDIR를 명시했으며, 소스에는 임시 작업 폴더를 `realpath`로 정규화하는 수정과 결정적 symlink 회귀 검사를 추가했다. 운영 immutable artifact 자체는 덮어쓰지 않았다.
3. 실제 배포 역할이 만든 private 멱등 기록 테이블의 소유자가 RPC 실행 역할과 달라 편집 저장이 거부됐다. `20261009003000_youtube_saved_recipe_result_owner_correction.sql`로 해당 private 테이블 소유자만 `postgres`로 맞췄다. 실제 DB는 **211개 이력**이며 외부 역할의 직접 접근은 계속 차단한다. 데이터 불변·worker catalog 불변을 트랜잭션 안에서 확인했다. 기존210 배포 증거는 당시 상태로 보존하며211 상태의 재배포 증거로 재사용하지 않는다.
