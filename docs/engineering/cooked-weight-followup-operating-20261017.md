- 오프라인 평가기는 명시적으로 전달받은 고정 입력만 메모리에서 계산한다. app/components의 운영 호출 지점은 없고 DB/네트워크/파일 쓰기·자동 수집·학습·정책 적용이 없다.

## 사용자 Mac Chrome 실제 확인

현재 Chrome 계정은 사용자가 기록 변경을 허용한 테스트 계정이다. 기존 QA 북의 새 추출 레시피를 독립 요리로 열어 검증했다. 실제 음식 조리·물리 측정이나 건강자료 입력을 한 것이 아니다.

1. 운영375×900 완료창에서 “일부 재료의 양을 확인하지 못해 전체무게를 추정하지 못했어요”가 보였다. 숫자 입력은1개이며 빈 상태, 개인 확인은 미선택/비활성, 팬트리는0개 선택이었다. 가로 넘침 없이 완료 저장 버튼이 보였다.
2. 같은 창을1440×1000에서도 확인했다. 안내와 선택 입력이 유지되고 필수 입력이나 자동 추정값 채움은 없었다.
3. 닫기로 취소하면 완료창이 사라지고 요리 완료 버튼이 다시 활성화됐다.375로 돌아와 재진입해도 무게는 빈칸, 팬트리 선택0이었다.
4. 빈칸으로 완료 저장1회 후 “2인분 · 요리 완료”가 나타났고 새로고침 후에도 유지됐다. 완료 버튼/창은0개였다.
5. 대상 QA batch를 읽기 전용 확인한 결과 생성됨·weight_status=missing·finished_weight_g=null이었다. 기존에 추가했던 플래너 항목은registered 그대로여서 독립 요리가 meal 상태를 바꾸지 않았다.
6. 최종 읽기 전용 집계는 V2·전체42작업·active0이며 배포 전 전체 작업 지문과 정책 해시는 동일했다.

## 남은 검증 경계

실제 운영에서 직접 확인한 새 안내 분기는 invalid_quantity다. 적당량·환산 근거 누락·일반 조리 조건·알 수 없는 code와 예상값 표시/실측 우선은 이번 표적 검사 및 이전 격리 컴포넌트 확인의 범위이며, 운영에서 모든 분기를 만들기 위해 추가 데이터를 생성하지 않았다. 네이버 공개 가입·새 추출기 품질·모든 레시피 정확도를 이번 성공으로 확대하지 않는다. 실제 정답 표본0·적용 범위 미확대는 그대로다.

무게 후속 때문에 새로 확인된 차단 오류는 없다. 앞선 YouTube 새로고침 진행 화면 누락/알림 창 잔존은 별도 보고서 `libfile_7adf500afbf48191bf5ad68c0968b282` version1의 후속 항목이며 이번 코드에 섞지 않았다. v85는 별도 검토·통합·운영 계약 확인 전까지 로컬 후보다.
