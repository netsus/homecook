# 레시피 상세·조회수·대기·개인 복제 저장 — 2026-09-27

상태: 피드백 묶음의 로컬 수정. 운영 DB와 웹에는 아직 반영하지 않았다.

## 조회수

상세 API의 증가 코드가 local-only에서 항상 null인 `createRemoteCompatibilityServiceRoleClient` 안에 있어 실행되지 않았다. 홈은 클릭 순간에만 화면 숫자를 +1하므로 복귀 후 실제 서버 숫자로 돌아왔다.

- 전용 `recipe-view` 내부 클라이언트는 정해진 조회수 RPC만 호출한다. 실제 저장에 성공한 반환값을 표시하며 실패 시 현재 저장값을 유지한다. 범용 UPDATE 우회와 가짜 +1 fallback은 제거한다.
- 신규 migration `20260927010000_recipe_view_count_local_scope.sql`은 기존 내부 scope 검사를 predecessor로 보존한다. 정확한 `recipe-view` + POST RPC 요청과 service_role만 허용하고, 공개·미삭제·공개 가능한 소유자의 레시피에만 원자적으로 증가시킨다.
- 홈에서 연 공개 레시피의 서버 확인 숫자만 탭 메모리에 최대 100개 보관한다. 상세에서 돌아와도 로딩한 페이지·검색·스크롤 문맥을 유지하면서 카드 숫자를 갱신한다. 계정 정보나 전체 레시피는 저장하지 않는다.
- 실제 격리 PostgreSQL의 공개/비공개/삭제/격리 계정·권한·기존 guard 보존·동시 8회 증가 검사가 통과했다. 운영 recipes의 사용자 트리거는 기존 계정 보호 함수임을 읽기 전용으로 확인했다. **조회수 저장 복구에는 이 migration의 별도 운영 반영이 필요하다.**

## 영양 표시

총열량의 `truncate`와 1인분 열량의 고정 한 줄 배치가 작은 화면에서 숫자를 잘랐다. 모바일에서는 두 줄로 배치하고 숫자의 말줄임을 제거했다. 반복되는 `최소` 접두사는 제거하되 partial/unknown, 인분 조절, 가변·고정값 계산은 유지한다. 일부 영양이 미확인이라는 안내는 `영양성분 더 보기`에 남긴다.

## 느린 요청과 세션 오류

응답 본문을 읽는 동안의 네트워크/시간초과와 일부 RPC fetch 실패가 세션 거절 409로 분류됐다. 전송 실패와 Auth 408/429/5xx는 기존 일시적 실패 503으로 구분하고 실제 만료·폐기·서명·권한 거절은 그대로 차단한다.

페이지 서버 처리 대기에는 공통 `app/loading.tsx`를 표시한다. 클라이언트는 요청이 진행되는 동안 기존 loading을 유지한다. 명시적으로 안전한 목록 GET만 한 번 재시도하며 각 읽기는 10초 제한이다. 조회수 부수효과가 있는 상세 GET, 로그아웃, 저장/수정/삭제는 자동 재실행하지 않는다. 실패가 확정되면 재시도 안내를 제공하고 무한 로딩으로 숨기지 않는다.

## 딸기우유푸딩 422

공개 원문은 푸딩과 딸기 콩포트의 재료를 나누어 적어 딸기·설탕·옥수수전분이 각각 두 행에 나타난다. 기존 POST 검증과 영양 계산이 ingredient_id만으로 중복을 판단해 원문을 그대로 저장해도 행 8·9·11에서 422를 반환했다.

- 개인 레시피 초안의 중복 기준은 `(ingredient_id, 정리된 component_label)`이다. 다른 구성의 같은 재료는 허용하고 같은 구성의 중복은 계속 거부한다.
- 계산용 행 ID와 제품 영양 버전 매핑을 행별로 분리해 모든 분량을 반영한다. 재료 카탈로그 ID나 DB 행을 병합하지 않는다.
- 재료 교체·삭제는 해당 구성의 조리 단계 참조만 변경한다. 어떤 구성인지 알 수 없는 단계는 임의 변경하지 않고 확인 안내를 남긴다.
- 422의 `error.fields`를 유지해 해당 재료/단계를 안내하고 입력 초안과 오류 포커스를 보존한다.
- 원문 12행·8단계로 수정 전 422와 수정 후 API 검증 통과를 재현했다. 실제 DB의 기존 stable 영양 guard 함수를 읽기 전용으로 호출해 12행과 수량 보존을 확인했다. API 성공 테스트의 저장 RPC는 mock이므로 실제 운영 저장 성공 검증과 구분한다. 이 수정에는 DB migration이 필요 없다.

## 확인 범위

영양 UI 9개, 구성별 저장 관련 32개, 전송/세션 관련 90개 검사와 조회수 API·홈 복귀·서버 client·격리 DB 검사를 선택 실행했다. 일부 테스트가 서로 겹치므로 총합으로 중복 집계하지 않는다. 통합 타입 검사와 수정 파일 정적 검사를 통과했다. 이번 작업에서는 운영 배포·백업/복원·자동 시작 검증을 실행하지 않았다. 실제 iPhone 화면과 운영 저장/조회수는 묶음 반영 단계에서 확인한다.
