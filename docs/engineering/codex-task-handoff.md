# Codex 작업 인수인계

## 상태

기능을 Stage별 새 Codex 작업으로 나누는 규칙은 폐지됐다. 현재 작업은 한 Codex task에서 계획, 구현, 로컬 확인, 리뷰와 PR까지 완료할 수 있다.

## 새 작업을 사용하는 경우

새 작업이나 서브에이전트는 다음처럼 병렬화가 실제로 도움이 될 때만 선택한다.

- 서로 겹치지 않는 구현을 동시에 진행할 때
- 큰 변경의 보안·DB·디자인 검토가 필요할 때
- 장시간 조사와 구현을 분리할 때

사용하지 않았다는 이유로 머지나 배포를 막지 않는다. 같은 task가 자신의 변경을 검토하고 수정할 수 있다.

## 간단한 인수인계 형식

필요할 때 아래 정보만 전달한다.

- 목표와 변경 범위
- 저장소와 브랜치
- 관련 공식 문서 또는 파일
- 이미 확인한 결과
- 남은 문제와 완료 조건

Stage 번호, OMO work item, closeout projection, 별도 승인 artifact와 task ID 기록은 필요하지 않다.
