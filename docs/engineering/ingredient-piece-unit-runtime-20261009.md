## 바뀐 동작

| 단위 계열 | 입력 표현 | 필요한 근거 |
| --- | --- | --- |
| 개수 | 개·알·통·piece·pieces | 같은 계열의 개당 중량, 기본 medium |
| 장 | 장 | 장당 중량 |
| 줄기 | 대·줄기 | 대/줄기당 중량 |

대파1줌은 기존 승인된30g, 대파1대는100g을 각각 선택한다. 양파1장이나 대파1모처럼 다른 단위의 근거를 빌리는 계산은 거부한다. 양배추의 기존 근거가1통900g이고 기존 레시피는 개수로 입력되어 있어 통을 개수 계열로 보존한다. 팩·캔·제품의 내용량을 개수로 취급하는 규칙은 추가하지 않았다.

근거의 `1개`, `1대`, `1줌` 표기는 관측 단위를 읽을 때만 앞의 정확한1을 허용한다. 사용자 입력 단위에 수량을 포함시키는 우회는 허용하지 않는다. 관측 수량이 정확히1이고 관측 무게와 연결 무게가 같으며 재료ID·상태·크기·근거ID·승인/활성/출처가 모두 맞아야 한다. 유일한 후보만 사용한다. 근거가 없으면 환산 누락으로 남기며 ml=g나 다른 크기 중량으로 대체하지 않는다.

## 구현과 과거 기록

- `lib/nutrition/ingredient-piece-units.mjs`에 순수 단위 규칙을 모았다. 레시피 영양·무게 계산과 근거 선택이 이를 공유한다. 별도 의존성이나 AI 호출은 없다.
- 근거 loader는 관측 단위·수량·무게와 실제 근거ID를 전달한다. 실제/초안 입력 guard에는 전체 유효 `piece_candidates`와 `selected_piece_weight_id`가 들어가 계산 후 저장 전 변경을 감지한다.
- 초안 계산의 수동 필드 복사에서도 두 필드를 보존한다. 처음에는 해당 경로에서 필드가 빠지는 실패를 재현하고 수정했다.
- 새 계산 기본 버전은 `recipe-nutrition-v3`이다. 과거 버전으로 저장된 snapshot을 읽을 때 재해석하거나 일괄 덮어쓰지 않는다.
- SQL 출처 검증·식사 미리보기·저장도 같은 단위/크기/관측 규칙을 따른다. 같은 수량의 과거 기록 수정은 저장된 영양 evidence를 유지한다. 다른 수량으로 계산할 때 잘못된 단위 근거를 재사용하지 않는다.
- 제품 라벨 기준 환산, 공식 영양 우선·AI fallback, 계정/세션/소유권·멱등성 보호는 유지한다. AI 자동 영양 보완을 켜지 않았다. 계량컵/밥숟갈의 기존 부피 정책은 이번 범위에서 변경하지 않았다.

## SQL과 권한

`20261009130000_ingredient_piece_unit_evidence.sql`은 private invoker helper5개를 만들고 현재 consumer6개의 본문만 보완한다. 기존 함수의 정확한 사전 정의 해시와 교체 위치 수를 확인하고 함수별 수정문을 합친 뒤 한 번씩 정의한다. 다른 변경이 먼저 반영되어 사전 정의가 다르면 중단한다. 기존 owner/ACL도 검증한다.

helper는 postgres 소유이고 public/anon/authenticated/service_role 직접 실행을 허용하지 않는다. 기존 공개 진입 함수가 postgres 권한으로 필요한 내부 검사를 호출한다. 새 테이블·컬럼·영양값·환산 무게 변경은 없다. AI 레시피 갱신 입력에도 관측 필드를 포함하되 자동 실행 정책은 유지한다. 이 migration은 이력 관리하에 한 번 적용하는 schema 변경이며 임의 반복 재생용 스크립트가 아니다.
