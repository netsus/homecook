## 4. 확정 결정

### D-01. 광고별 Hero 선택

URL의 `utm_content`, 광고용 `ad_variant`, 또는 개발용 `variant` 값으로 Hero를 고른다. 인식하지 못한 값이나 직접 방문은 기본 Hero를 사용한다.

| 변형 | 값 | 제목 | 첫 시각 |
|---|---|---|---|
| A 반복 검색·입력 | `hook_reentry`, `a` | 같은 재료, / 또 찾고 또 입력하나요? | 유튜브 레시피의 돼지고기·양파·대파를 식단 앱에서 하나씩 다시 검색하는 대기 화면 |
| B 조리 무게 반영 | `hook_cooked_weight`, `b` | 제육볶음 300g, / 정확히 몇 kcal? | 요리 전 재료·요리 후 완성·내가 먹은 양의 3단 비교와 저울 숫자 |
| C 내 집밥 영양성분 | `hook_calorie_quiz`, `c` | 내 집밥에도 / 영양성분표가 있다면? | 집밥 사진과 내 레시피 기준 영양 카드 |
| D 다른 음식으로 기록 | `hook_workaround`, `d` | 내가 만든 집밥을 / 왜 다른 음식으로 기록하지? | 내 레시피와 검색해서 고른 일반 음식의 직접 비교 |
| 기본 | 없음·기타 | 집밥도 정확하게 기록할 수 있을까? | 광고와 무관한 중립적인 집밥 기록 시각 |

Hero 보조 문구는 광고가 약속한 효용을 한 문장으로 이어받고 CTA는 `테스트 시작하기 →`로 통일한다. A/B/C/D 이후 퀴즈는 완전히 동일하다. 첫 운영 광고는 A/B/C 세 가지로 집중하며, 같은 메시지로 피드용 4:5와 Reels/Stories용 9:16을 함께 제공한다. CTA와 하단 신뢰 문구는 모두 동일하게 유지한다. D 광고 집행은 보류하되 과거 링크와 수집 데이터가 깨지지 않도록 `hook_workaround`와 `d` Hero 경로는 호환용으로 남긴다.

`반복 입력 제거`, `조리 무게 반영`, `내 집밥 영양성분`, `대체 기록 해소`는 내부 실험 가설명일 뿐 실제 광고 이미지에는 노출하지 않는다. 실제 광고에는 브랜드, 한 개의 핵심 질문, 한 개의 보조 문장, 공통 CTA와 신뢰 문구만 표시한다. A는 코랄, B는 밝은 시안·노랑, C는 밝은 보라·코랄·노랑을 보조색으로 써 서로 구분하고 공통 CTA만 브랜드 블루를 유지한다. 제목은 A의 `또 찾고 또 입력`, B의 `몇 kcal`, C의 `영양성분표`만 색으로 강조한다. 핵심 시각에는 큰 바깥 테두리를 두지 않고 랜딩에서는 원본 비율을 보존해 자르지 않는다. A는 돼지고기·양파·대파가 적힌 유튜브 레시피와 같은 재료를 하나씩 다시 검색하는 식단 앱을 나란히 보여주며, 검색 원과 결과 자리 표시선으로 로딩을 표현한다. 화면 사이 방향 표시는 설명 없이 유지하고 별도 설명형 문구는 넣지 않는다. B는 `조리 후 달라진 무게, / 칼로리는 어떻게 계산할까?`를 보조 문구로 사용하고, 생재료에서 완성 음식과 섭취량으로 이어지는 무게 단계를 제목 가까이 배치한다. 세 저울은 확대된 단계명·무게와 함께 파란 LCD 바탕의 짙은 숫자를 사용하며, 랜딩 B는 5:3 비율로 위아래 내부 여백을 줄인다. C도 5:3 랜딩 비율로 여백을 줄이고 저울 중앙의 `320g`과 크게 표시한 탄·단·지 수치를 사용한다.

A의 반복 검색 장면은 `제육볶음 레시피` 카드에 돼지고기 600g·양파 200g·대파 100g을 표시하고, 식단 기록 카드에서 동일한 세 재료를 각각 `검색...`하는 입력 행과 별도 로딩 행으로 대응시킨다. 레시피 사진은 저울 없는 흰 배경 음식 사진을 사용하며, 4:5와 9:16 광고에서는 본문 가까이에 두 카드를 크게 배치한다.

### D-02. 설문 분기

프로토타입에서는 Non-core 조기 종료를 사용하지 않는다. 모든 사용자가 4문항을 완료한다.

이유:

- 결과는 Q3으로 결정되므로 Q3 전 종료 시 결과를 만들 수 없다.
- 4문항은 짧고 자동 이동하므로 부담이 크지 않다.
- 광고별 완료율과 결과 분포를 같은 조건에서 비교할 수 있다.

조기 종료 실험은 실제 분석·이메일 연동을 붙이는 다음 단계로 미룬다.

### D-03. 설문 상호작용

- 모든 문항은 단일 선택이다.
- 선택 즉시 선택 상태와 체크를 보여준다.
- 약 300ms 후 자동으로 다음 문항으로 이동한다.
- 별도 `다음` 버튼은 없다.
- Q2부터 뒤로가기를 제공하고, 이전 답변을 유지한다.
- 자동 이동 중 중복 탭은 한 번만 처리한다.
- Q4 선택 후 바로 결과 화면으로 이동한다.

설문 카피를 다음으로 고정한다.

| 문항 | 질문 | 선택지 |
|---|---|---|
| Q1 | 평소 칼로리나 탄단지를 / 얼마나 자주 기록하나요? | 거의 매일 / 주 3~5일 / 주 1~2일 / 거의 안 함 / 안 함 |
| Q2 | 일주일에 집밥을 / 몇 끼 정도 먹나요? | 거의 안 먹음 / 1~2끼 / 3~5끼 / 6끼 이상 |
| Q3 | 집밥은 주로 / 어떻게 기록하나요? | 집밥은 기록하지 않음 / 먹은 양을 눈대중으로 기록 / 딱 맞는 음식이 없어 비슷한 음식이나 1인분으로 기록 / 재료와 음식 무게까지 재서 기록 |
| Q4 | 집밥을 기록할 때 / 가장 불편한 것은? | 재료와 양을 하나씩 입력하는 것 / 완성된 음식과 먹은 양을 재는 것 / 딱 맞는 음식이 없어 비슷한 걸 찾아야 하는 것 / 별로 불편하지 않음 |

Q2에는 `직접 만들거나 가족이 만든 음식 모두 포함`을 보조 설명으로 표시한다.

### D-04. 결과 판정

결과는 Q3 하나로만 결정한다. Q1, Q2, Q4는 결과 점수에 영향을 주지 않는다.

| Q3 답변 | 결과 |
|---|---|
| 집밥은 기록하지 않음 | 집밥 패스형 |
| 먹은 양을 눈대중으로 기록 | 눈대중 장인 |
| 딱 맞는 음식이 없어 비슷한 음식이나 1인분으로 기록 | 성분 추적러 |
| 재료와 음식 무게까지 재서 기록 | 프로 계량러 |

### D-05. `성분 추적러` 의미 정렬

사용자가 확정한 이름 `성분 추적러`는 유지한다. 다만 기존의 `고추장 17g도 그냥 넘어가지 않는 사람`은 프로 계량러와 의미가 겹치므로 구현 카피에서는 사용하지 않는다.

확정 카피:

> 내가 만든 제육볶음과 가장 비슷한 영양정보를 끝까지 찾는 사람.

> 딱 맞는 음식이 없어 오늘도 검색 결과를 추적하고 있습니다. 당신에게 필요한 건 더 긴 검색이 아니라 내 레시피를 바로 기록하는 자동화일지도.

캐릭터와 결과 화면의 구도는 `성분추적러.png`를 유지한다.

### D-06. 나머지 결과 카피

PRD의 전체 문장을 제품 카피로 사용한다. 생성 화면의 짧아진 문장은 시각 배치 참고일 뿐이다.

- 집밥 패스형
  - 강조: `닭가슴살까지는 기록했는데 김치찌개에서 앱을 닫는 타입.`
  - 설명: `기록할 마음은 있었지만 재료가 7개를 넘어가는 순간 인간의 영역이 아니라고 판단합니다.`
- 눈대중 장인
  - 강조: `칼로리는 과학이지만 내 눈도 꽤 정확하다고 믿는 편.`
  - 설명: `비슷한 메뉴를 찾아 빠르게 기록하는 실용주의자. 문제는… 오늘 제육볶음이 검색한 제육볶음과 같다는 보장은 없다.`
- 프로 계량러
  - 강조: `완성 음식까지 저울에 올렸다면 당신은 이미 상위 기록러.`
  - 설명: `재료 무게 ✔ 완성 무게 ✔ 먹은 무게 ✔ 문제는 이걸 매번 계산하는 데 시간이 너무 든다는 것.`

공통 결과 CTA:

- 보조: `내 결과 공유하기`
- 전환 문구: `그런데 집밥 기록이 20초 만에 끝난다면?`
- 주 CTA: `무먹으로 20초 체험하기 →`

### D-07. 결과 공유

- 지원 환경에서는 `navigator.share`로 유형명과 현재 결과 URL을 공유한다.
- 지원하지 않거나 사용자가 취소하면 오류 화면으로 보내지 않는다.
- 지원하지 않는 환경에서는 링크 복사로 대체하고 `링크를 복사했어요.`를 짧게 알린다.
- 공유용 `1200×630` OG 이미지를 로컬 자산으로 제공하고 `og:*`, Twitter Card 메타 태그를 설정한다.
- KakaoTalk 등 외부 서비스의 실제 카드 렌더링은 공개 HTTPS 배포와 크롤러 접근이 있어야 확인할 수 있다. localhost에서는 URL만 보일 수 있다.

### D-08. `20초`의 범위

`20초 체험`은 결과 CTA를 누른 시점부터 제육볶음이 첫 주간 식단에 들어간 시점까지를 뜻한다. 완제품 추가와 베타 신청 시간은 포함하지 않는다.

- 자동 애니메이션 한 번은 0.8초를 넘지 않는다.
- 사용자가 내용을 읽는 시간은 보장 시간에 포함하지 않는 마케팅 표현으로 취급한다.
- 사용자 테스트에서 반복적으로 30초를 넘으면 공개 카피를 `약 20초 체험`으로 조정한다.

### D-09. 체험 데이터 잠금

| 상태 | 값 |
|---|---|
| 돼지고기 | `600g → 520g` |
| 예상·실제 완성 무게 | `1,200g → 1,180g` |
| 먹은 양 | `320g` |
| 섭취 열량 | `487 kcal` |
| 탄수화물·단백질·지방 | `31g · 39g · 22g` |
| 첫 식단 합계 | `1,120 → 1,607 kcal` |
| 첫 단백질 합계 | `72 → 111g` |
| 완제품 | `더:단백 드링크 초코`, `250ml`, `105 kcal`, `단백질 20g` |
| 두 번째 합계 | `1,607 → 1,712 kcal` |

`와이어프레임3.png`에 보이는 제육볶음 `620 kcal`는 오류이며 사용하지 않는다. 제육볶음 한 끼는 항상 `487 kcal`이다.

### D-10. 식단 Payoff

- `식단에 기록하기 →`를 누르기 전에는 제육볶음이 식단에 없어야 한다.
- 누르면 `제육볶음 320g` 행이 집중 이펙트와 함께 들어오고 열량·탄수화물·단백질·지방이 count-up 된다.
- 이 화면은 실제 무먹의 식사 기록 화면 밀도와 토큰을 따르되, 퍼널을 이탈시키는 하단 탭은 넣지 않는다.
- 완제품 `+ 기록하기` 후 같은 저녁 행에 제품이 집중 이펙트와 함께 추가되고 네 영양 요약이 다시 증가한다.

- 식단의 이전·다음 주 버튼은 같은 Chevron 계열 아이콘을 좌우 대칭으로 사용한다. 요일·날짜 박스는 상하 패딩을 줄여 50px 이하로 유지한다.
- 두 식단 CTA는 콘텐츠 높이가 아니라 모바일 화면 하단 안전영역에 고정한다. 단백질 음료 행이 삽입되고 영양 수치가 변하는 동안에도 버튼의 y 위치가 달라지지 않는다.
- 베타 로고는 콘텐츠 왼쪽 위에 두고 이후 캐릭터·카피·폼을 위로 당긴다. 신청 완료 화면은 무스크롤이며 `처음으로 돌아가기`를 다른 화면과 같은 브랜드 블루 기본 버튼으로 표시한다.

### D-22. 2026-09-04 A/B/C Hero 실제 UI 전환 확정

- A/B/C 랜딩의 증명 영역은 합성된 `hero-a/b/c-solution.png` 한 장을 화면에 넣지 않는다. 카드·헤더·재료량·조리 전후 무게·섭취량·열량·탄단지·완료 문구·화살표를 React 실제 요소로 렌더링한다.
- 이미지로 남기는 것은 음식 사진뿐이다. A/C는 `jeyuk-recipe-clean.png`, B는 `jeyuk-on-scale.png`를 사용하고 카드 안에서 이전보다 크게 표시한다.
- A는 레시피 카드에서 `돼지고기 600g · 양파 200g · 대파 100g`이 자동 정리 완료 카드로 이어진다.
- B는 완성 무게 `1,083g` 저울 사진과 `먹은 양 300g`을 분리해 보여주고, 오른쪽에서 `1,420g → 1,083g → 300g` 계산 근거를 보여준다.
- C는 내 제육볶음 레시피에서 실제 영양 카드 `487 kcal / 31g / 39g / 22g`로 이어진다.
- 카드 헤더는 최소 11px 굵은 글씨, 핵심 수치는 12~16px, C의 `kcal` 단위는 최소 14px을 유지한다. 전체 영역은 기존 5:3 크기와 `390×844` 무스크롤을 유지한다.

### D-23. 2026-09-04 체험·식단·베타 위치 안정화 확정

- 체험 상단 진행 표시는 오른쪽에 모인 `24px × 5개` 짧은 pill 형태로 사용한다. 뒤로가기와 진행 표시 사이를 억지로 채우는 전폭 바는 사용하지 않는다.
- 체험 2는 설탕까지 여섯 재료를 온전히 보여준다. `오늘은 돼지고기를 조금 덜 넣었어요.` 안내는 `10px 12px`의 컴팩트 패딩을 사용하고, 하단 작업 버튼은 안내 바로 아래에 둔다.
- 체험 3은 저울 바로 아래에 44px 고정 안내 슬롯을 항상 예약한다. 반영 전 버튼과 반영 후 `다음` 버튼은 동일한 y 위치를 유지한다.
- 식단에서는 오늘 저녁과 추가된 단백질 음료가 내일 미리보기보다 우선한다. 내일 카드는 모바일 화면 아래쪽에 고정해 CTA 뒤 배경처럼 보이게 하고 오늘 식단 높이에 영향을 주지 않는다.
- 베타 신청 로고는 별도 행을 차지하지 않고 뒤로가기 버튼 오른쪽 같은 행에 배치한다.

### D-24. 2026-09-04 완성 저울·공통 CTA·완료 축하 확정

- 체험 3은 빈 저울 대신 완성된 제육볶음이 올라간 `jeyuk-on-scale.png`를 사용하고 LCD 안에 `1,180g`을 실제 텍스트로 표시한다.
- 체험 4의 `320g`은 같은 저울 LCD 표시창의 수직 중앙에 배치한다.
- 두 식단 CTA는 내일 미리보기의 자식 요소로 두지 않는다. 모바일 화면의 좌우 24px, 하단 안전영역 기준으로 다른 체험 CTA와 같은 `342×54px` 위치를 사용한다.
- 단백질 음료가 추가되는 동안에도 CTA의 폭과 위치가 변하거나 잘리지 않는다.
- 신청 완료 캐릭터는 처음 등장할 때 pop-in되고 이후 가볍게 상하로 움직인다. 캐릭터 둘레의 실제 별 아이콘 8개는 색과 시간차를 달리해 반복 축하 효과를 만든다.
