## 0. 이번 랜딩의 목적

이번 실험에서 확인하려는 것은 세 가지다.

**1. Problem**

식단을 기록하면서 집밥을 먹는 사람들은 실제로 집밥 기록 과정에서 불편을 겪는가?

**2. Accuracy Need**

사람들은 집밥을 어느 정도까지 정확하게 기록하려고 실제 행동하고 있는가?

**3. Demand**

무먹의 기록 방식을 직접 체험한 사람이 실제로 베타 이메일까지 남기는가?

이번 랜딩에서는

> “무먹이 있으면 쓰시겠어요?”

라고 묻지 않는다.

**현재 행동 → 실제 불편 → 무먹 체험 → 이메일 제출**

순서로 행동에 가까운 증거를 수집한다.

# 10. 결과 유형 분류

Q4가 핵심 기준이다.

정밀 행동:

- P1 = 실제 재료와 양
- P2 = 완성 음식 무게
- P3 = 먹은 음식 무게
- P4 = 먹은 양만큼 영양 계산

대략 행동:

- A = 비슷한 음식 / 1인분

미기록:

- N = 집밥 기록 안 함

---

## ⚖️ 프로 계량러

P1~P4 중 **3개 이상** 선택.

특히 완성중량과 섭취중량까지 측정하는 사용자.

---

## 🧾 성분 추적러

프로 계량러가 아니면서 P1~P4 중 **하나 이상** 선택.

직접 재료나 영양성분을 챙겨 기록하는 사용자.

---

## 👀 눈대중 장인

위 두 유형이 아니면서

`비슷한 음식이나 1인분으로 대충 기록`

선택.

---

## 👻 집밥 패스형

- `집밥은 기록하지 않았다`
- 식단 자체를 거의 기록하지 않음
- 집밥을 거의 먹지 않음
- 위 유형에 속하지 않음

---

## 중복 우선순위

**프로 계량러 → 성분 추적러 → 눈대중 장인 → 집밥 패스형**

# 26. 지원서에서 사용할 근거 구조

최종 숫자가 나오면 다음 구조로 작성한다.

> 정식 출시 전 온라인 광고를 통해 집밥 식단기록 수요를 검증했습니다.
>
> 식단을 주 3일 이상 기록하고 집밥을 주 3끼 이상 먹는 핵심 사용자 **[N]명** 중 **[X]%**가 집밥을 기록하면서 실제 불편을 경험했습니다.
>
> 이 중 **[A]%**는 실제 재료와 양을 직접 입력했고, **[B]%**는 완성 음식 또는 자신이 먹은 음식의 무게까지 측정한 경험이 있었습니다.
>
> 반면 **[C]%**는 번거로움 때문에 비슷한 음식이나 1인분으로 대략 기록하거나 집밥 기록을 생략했습니다.
>
> 이후 사용자가 `유튜브 레시피 → 실제 재료 수정 → 완성중량 → 섭취량 → 영양성분 → 주간 식단 기록`의 무먹 핵심 흐름을 직접 체험하도록 했으며, 체험 완료자 중 **[D]%**가 실제 베타 이메일을 제출했습니다.
>
> 이를 통해 창업자의 개인적인 불편에서 시작한 문제가 외부 식단기록 사용자에게도 반복적으로 존재하고, 무먹의 해결방식을 직접 사용해볼 의향이 있음을 행동으로 확인했습니다.
