# 무먹 모바일 광고 퍼널 테스트 명세

- 상태: 구현·검증 완료 테스트 계약
- 기준 문서: `product-decisions.md`
- 원칙: 테스트를 먼저 작성하고 실패를 확인한 뒤 최소 구현으로 통과시킨다.

## 1. 테스트 우선순위

- P0: 핵심 흐름, 데이터 일관성, 외부 요청 없음, 작은 모바일 사용성
- P1: 공유 대체 동작, 뒤로가기, 접근성, 모션 감소, 오류 회복
- P2: 미세한 시각 차이와 애니메이션 감도

P0가 하나라도 실패하면 구현 완료가 아니다.

## 2. 고정 테스트 데이터

```text
ingredients:
  pork: 600g -> 520g
  onion: 200g
  green_onion: 100g
  gochujang: 60g
  soy_sauce: 40g
  sugar: 25g

cooked_weight: 1200g -> 1180g
portion: 320g
meal: 487 kcal / carbs 31g / protein 39g / fat 22g
planner: 1120 -> 1607 kcal / protein 72 -> 111g
packaged_food: 250ml / 105 kcal / carbs 7g / protein 20g / fat 0.6g / sugar 0.8g
planner_after_packaged_food: 1607 -> 1712 kcal
```

어떤 화면에서도 제육볶음을 `620 kcal`로 표시하면 실패다. 완제품에 이전 값 `110 kcal`, 합계 `1,717 kcal`, 제품명 `얼티브 프로틴 초코`가 남아 있어도 실패다.

## 3. P0 행동 테스트

### Hero 라우팅

- `H-01`: 파라미터가 없으면 기본 Hero 제목과 CTA가 보인다.
- `H-02`: `utm_content=hook_reentry`는 A Hero를 보여준다.
- `H-03`: `utm_content=hook_cooked_weight`는 B Hero를 보여준다.
- `H-04`: `utm_content=hook_calorie_quiz`는 C Hero를 보여준다.
- `H-05`: `utm_content=hook_workaround`는 D Hero를 보여준다.
- `H-06`: 개발용 `variant=a|b|c|d`도 같은 Hero를 선택한다.
- `H-07`: 알 수 없는 값은 오류 없이 기본 Hero로 돌아간다.
- `H-08`: 모든 변형의 CTA는 같은 Q1으로 이동한다.
- `H-09`: 광고별 Hero 외 Q1 이후 화면과 데이터는 동일하다.

### 4문항 설문

- `Q-01`: Q1 진입 시 `1 / 4`와 첫 진행 상태가 보인다.
- `Q-02`: 선택 전에는 어떤 답도 선택 상태가 아니다.
- `Q-03`: 답을 누르면 한 항목에만 선택·체크 상태가 생긴다.
- `Q-04`: 선택 후 자동으로 다음 문항으로 이동한다.
- `Q-05`: 설문 화면에는 `다음` 버튼이 없다.
- `Q-06`: Q1~Q4의 질문과 선택지가 제품 결정표와 정확히 일치한다.
- `Q-07`: Q1·Q2에서 Non-core 답을 골라도 Q3·Q4를 계속 진행한다.
- `Q-08`: 빠르게 여러 번 눌러도 문항을 건너뛰거나 답이 두 번 기록되지 않는다.
- `Q-09`: Q4 선택 후 Q3 답에 맞는 결과 화면으로 이동한다.
- `Q-10`: 이메일 화면 전까지 텍스트 입력 요소가 존재하지 않는다.

### 결과 판정

- `R-01`: `집밥은 기록하지 않음`은 집밥 패스형이다.
- `R-02`: `먹은 양을 눈대중으로 기록`은 눈대중 장인이다.
- `R-03`: `딱 맞는 음식이 없어 비슷한 음식이나 1인분으로 기록`은 성분 추적러다.
- `R-04`: `재료와 음식 무게까지 재서 기록`은 프로 계량러다.
- `R-05`: Q1, Q2, Q4를 바꿔도 Q3가 같으면 결과가 같다.
- `R-06`: 결과마다 `public/assets/funnel/characters/`의 정확한 투명 캐릭터 파일과 고정 카피가 보인다.
- `R-07`: 폐기된 외눈 밥그릇 캐릭터는 결과·Hero·베타에 나타나지 않는다.
- `R-08`: 모든 결과에서 공유 행동과 `무먹으로 20초 체험하기 →`가 동작한다.

### 5단계 체험

- `E-01`: 결과 CTA는 체험 1/5로 이동한다.
- `E-02`: 각 단계는 `체험 N / 5 · 단계명`과 5개 진행 구간을 가진다.
- `E-03`: 완료·현재 구간만 파란색이다.
- `E-04`: 체험 1 CTA를 누르기 전에는 성공 메시지가 보이지 않는다.
- `E-05`: 체험 1은 `public/assets/funnel/food/recipe-jeyuk-thumbnail.png`를 표시한다.
- `E-06`: 체험 1 CTA 후 `레시피를 가져왔어요`가 보이고 체험 2로 이동한다.
- `E-07`: 체험 2는 여섯 재료와 정확한 중량을 표시한다.
- `E-08`: 체험 2의 돼지고기 값은 사용자 입력 없이 `600g → 520g`으로 바뀐다.
- `E-09`: 체험 2의 `다음 →`은 체험 3으로 이동한다.
- `E-10`: 체험 3은 먼저 예상 완성 무게 `1,200g`을 표시한다.
- `E-11`: `저울로 재보니 1,180g`을 누르면 `1,180g`과 안내 문구가 보인다.
- `E-12`: 체험 3에는 숫자 입력과 키패드가 없다.
- `E-13`: 체험 4는 `public/assets/funnel/food/jeyuk-on-scale.png`와 `320g`을 표시한다.
- `E-14`: 저울 이미지 자체에는 숫자·문구·브랜드가 없고 `320g`은 접근 가능한 UI 텍스트다.
- `E-15`: `320g 입력하기` 외 복수 중량 선택지는 없다.
- `E-16`: 체험 5는 `487 kcal`, `31g`, `39g`, `22g`을 정확히 표시한다.
- `E-17`: `식단에 기록하기 →` 전에는 제육볶음이 주간 식단에 없다.

### 첫 식단 Payoff와 완제품

- `P-01`: `식단에 기록하기 →` 후 `제육볶음 320g` 행이 나타난다.
- `P-02`: 첫 식단 합계는 `1,120 → 1,607 kcal`이다.
- `P-03`: 단백질 합계는 `72 → 111g`이다.
- `P-04`: 완제품을 기록하기 전에는 완제품 행이 없다.
- `P-05`: 완제품 화면은 `더:단백 드링크 초코`, `250ml`, `105 kcal`, `단백질 20g`을 표시한다.
- `P-06`: `+ 기록` 후 제육볶음 아래에 완제품 행이 추가된다.
- `P-07`: 두 번째 합계는 `1,607 → 1,712 kcal`이다.
- `P-08`: 베타 CTA는 완제품 반영 뒤 나타난다.
- `P-09`: 완제품 카드에는 `제품 예시` 안내가 보인다.

### 베타 신청

- `B-01`: 베타 화면은 전체 흐름에서 유일한 텍스트 입력을 가진다.
- `B-02`: 빈 이메일 제출은 완료 화면으로 이동하지 않는다.
- `B-03`: 명백히 잘못된 이메일은 입력창 가까이에 오류를 표시한다.
- `B-04`: 오류는 색 외에 문장으로도 전달한다.
- `B-05`: 유효한 이메일 제출 중 버튼 중복 클릭이 막힌다.
- `B-06`: 유효한 이메일은 처리 상태 뒤 완료 화면으로 이동한다.
- `B-07`: 완료 화면은 `신청이 완료됐어요!`와 안내 문구를 표시한다.
- `B-08`: `처음으로 돌아가기`는 답변·체험·이메일 상태를 초기화한다.
- `B-09`: 초기화 후에도 유입된 광고 Hero 변형은 유지한다.

## 4. 외부 연동 금지 테스트

- `N-01`: 전체 핵심 흐름에서 외부 도메인으로 fetch/XHR 요청이 0건이다.
- `N-02`: YouTube iframe, 영상 재생, YouTube API 요청이 없다.
- `N-03`: 이메일 제출 시 네트워크 요청과 로컬 영구 저장이 없다.
- `N-04`: 분석·광고·추적 스크립트가 로드되지 않는다.
- `N-05`: 새로고침하면 이메일과 설문 답변이 남지 않는다.
- `N-06`: 공유는 브라우저의 native share 또는 클립보드만 사용한다.
- `N-07`: 이미지·폰트·스타일시트도 외부 URL에서 불러오지 않는다.

## 5. P1 상호작용·접근성 테스트

### 뒤로가기와 회복

- `I-01`: Q2~Q4에서 뒤로가면 이전 문항과 선택 답이 복원된다.
- `I-02`: 결과에서 뒤로가면 Q4로 돌아가며 답이 유지된다.
- `I-03`: 체험 중 뒤로가도 진행 상태가 깨지지 않는다.
- `I-04`: 새로 시작하면 항상 Hero부터 깨끗한 상태로 시작한다.

### 공유

- `S-01`: native share 지원 시 유형명과 현재 URL이 전달된다.
- `S-02`: native share 미지원 시 링크 복사로 대체된다.
- `S-03`: 공유 취소는 오류로 표시되지 않는다.
- `S-04`: 클립보드 실패 시 사용자가 다시 시도할 수 있는 안내가 보인다.

### 접근성

- `A-01`: 모든 버튼·선택지는 접근 가능한 이름을 가진다.
- `A-02`: 선택지는 키보드로 이동하고 선택할 수 있다.
- `A-03`: 포커스 표시가 배경과 구분된다.
- `A-04`: 터치 목표는 최소 `44×44px`이다.
- `A-05`: 진행 단계와 자동 변경 결과가 스크린리더에 전달된다.
- `A-06`: 본문·보조 글자·버튼의 색 대비가 기준을 만족한다.
- `A-07`: 선택·오류·성공을 색만으로 구분하지 않는다.
- `A-08`: 이메일 오류가 입력과 프로그램상 연결된다.
- `A-09`: `prefers-reduced-motion`에서 자동 이동을 제외한 장식 애니메이션과 count-up이 즉시 완료된다.
- `A-10`: 200% 확대에서도 주요 CTA와 입력이 가려지지 않는다.

## 6. 모바일 레이아웃 테스트

필수 viewport:

| 이름 | CSS 크기 | 목적 |
|---|---:|---|
| 기준 | `393×852` | 와이어프레임과 기본 비교 |
| Android 기준 | `427×952` | Pixel 10 런타임·긴 화면 검증 |

앱의 실제 내부 화면은 iPhone `393×852`, Pixel 10 `427×952` 두 런타임으로 검증한다. 더 좁은 브라우저 창에서는 런타임이 기기 프레임을 비율 축소하므로 앱 내부 CSS 좌표가 `320×568`로 바뀌지는 않는다.

각 viewport에서 확인한다.

- 가로 스크롤이 없다.
- CTA, 공유, 이메일 입력이 홈 인디케이터에 가려지지 않는다.
- 결과 화면은 내용이 길면 자연스럽게 세로 스크롤된다.
- Sticky CTA가 본문 마지막 내용을 덮지 않는다.
- 캐릭터가 잘리거나 비율이 늘어나지 않는다.
- 캐릭터 PNG 바깥 영역은 실제 투명 알파이며 파란 배경이나 체크무늬가 보이지 않는다.
- Q4의 긴 선택지가 잘리지 않고 터치 영역 전체가 동작한다.

## 7. 시각 회귀 테스트

비교 원본:

- Hero·설문: `../와이어프레임1.png`
- 체험·첫 식단: `../와이어프레임2.png`
- 완제품·베타: `../와이어프레임3.png`
- 결과 4종: 현재 폴더의 개별 결과 화면 PNG

보드는 여러 화면을 한 장에 모은 와이어프레임이므로 실제 비교에서는 각 화면을 같은 비율로 분리해 참고하고, 구현 캡처는 `393×852` 앱 화면만 사용한다.

반드시 비교할 항목:

- Pretendard 계열 글꼴, 크기, 굵기, 줄바꿈
- 20~24px 좌우 여백과 세로 리듬
- `#00A1FF`와 선택 배경색
- 이미지 선명도·비율·크롭
- 정확한 한국어 카피와 숫자
- 주요 CTA의 높이·폭·하단 안전 여백

허용된 의도적 차이:

- 폐기된 외눈 밥그릇 캐릭터 대신 공식 무먹 로고 사용
- `와이어프레임3.png`의 잘못된 `620 kcal`를 `487 kcal`로 수정
- 결과 화면의 성분 추적러 카피를 제품 결정표 문구로 수정
- 선택 전·선택 후·성공 상태를 각각 분리
- 작은 화면에서 자연스러운 스크롤 사용
