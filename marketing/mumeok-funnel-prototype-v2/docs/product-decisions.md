## 4. 확정 결정

### D-01. 광고별 Hero 선택

URL의 `utm_content`, 광고용 `ad_variant`, 또는 개발용 `variant` 값으로 Hero를 고른다. 인식하지 못한 값이나 직접 방문은 기본 Hero를 사용한다.

| 변형 | 값 | 제목 | 첫 시각 |
|---|---|---|---|
| A 재입력 | `hook_reentry`, `a` | 왜 레시피에 다 있는데 / 내가 또 입력하지? | 레시피 재료와 식단 앱 재검색 비교 |
| B 조리 후 중량 | `hook_cooked_weight`, `b` | 요리 전 1,420g → 요리 후 1,083g / 그럼 내가 먹은 300g은 몇 kcal일까? | 조리 전·후·섭취량 3단 비교 |
| C 칼로리 퀴즈 | `hook_calorie_quiz`, `c` | 이 제육볶음 300g, / 몇 kcal일까요? | 300g 칼로리 선택 문제 |
| D 비슷한 음식 | `hook_workaround`, `d` | 식단은 꼼꼼히 기록하는데 / 집밥만 ‘비슷한 음식’으로 넣고 있었습니다. | 요리 계획과 실제 기록의 불일치 |
| 기본 | 없음·기타 | 집밥도 정확하게 기록할 수 있을까? | 광고와 무관한 중립적인 집밥 기록 시각 |

모든 Hero의 보조 문구는 `30초 테스트로 나의 집밥 기록 타입을 알아보세요.`이고 CTA는 `테스트 시작하기 →`이다. A/B/C/D 이후 퀴즈는 완전히 동일하다.

### D-02. 설문 분기

프로토타입에서는 Non-core 조기 종료를 사용하지 않는다. 모든 사용자가 4문항을 완료한다.

이유:

- 결과는 Q3으로 결정되므로 Q3 전 종료 시 결과를 만들 수 없다.
- 4문항은 짧고 자동 이동하므로 부담이 크지 않다.
- 광고별 완료율과 결과 분포를 같은 조건에서 비교할 수 있다.

조기 종료 실험은 실제 분석·이메일 연동을 붙이는 다음 단계로 미룬다.

### D-03. 설문 상호작용

- 모든 문항은 단일 선택이다.
- 선택 즉시 선택 상태와 체크를 보여준다.
- 약 300ms 후 자동으로 다음 문항으로 이동한다.
- 별도 `다음` 버튼은 없다.
- Q2부터 뒤로가기를 제공하고, 이전 답변을 유지한다.
- 자동 이동 중 중복 탭은 한 번만 처리한다.
- Q4 선택 후 바로 결과 화면으로 이동한다.

설문 카피를 다음으로 고정한다.

| 문항 | 질문 | 선택지 |
|---|---|---|
| Q1 | 평소 칼로리나 탄단지를 / 얼마나 자주 기록하나요? | 거의 매일 / 주 3~5일 / 주 1~2일 / 거의 안 함 / 안 함 |
| Q2 | 일주일에 집밥을 / 몇 끼 정도 먹나요? | 거의 안 먹음 / 1~2끼 / 3~5끼 / 6끼 이상 |
| Q3 | 집밥은 주로 / 어떻게 기록하나요? | 집밥은 기록하지 않음 / 먹은 양을 눈대중으로 기록 / 딱 맞는 음식이 없어 비슷한 음식이나 1인분으로 기록 / 재료와 음식 무게까지 재서 기록 |
| Q4 | 집밥을 기록할 때 / 가장 불편한 것은? | 재료와 양을 하나씩 입력하는 것 / 완성된 음식과 먹은 양을 재는 것 / 딱 맞는 음식이 없어 비슷한 걸 찾아야 하는 것 / 별로 불편하지 않음 |

Q2에는 `직접 만들거나 가족이 만든 음식 모두 포함`을 보조 설명으로 표시한다.

### D-04. 결과 판정

결과는 Q3 하나로만 결정한다. Q1, Q2, Q4는 결과 점수에 영향을 주지 않는다.

| Q3 답변 | 결과 |
|---|---|
| 집밥은 기록하지 않음 | 집밥 패스형 |
| 먹은 양을 눈대중으로 기록 | 눈대중 장인 |
| 딱 맞는 음식이 없어 비슷한 음식이나 1인분으로 기록 | 성분 추적러 |
| 재료와 음식 무게까지 재서 기록 | 프로 계량러 |

### D-05. `성분 추적러` 의미 정렬

사용자가 확정한 이름 `성분 추적러`는 유지한다. 다만 기존의 `고추장 17g도 그냥 넘어가지 않는 사람`은 프로 계량러와 의미가 겹치므로 구현 카피에서는 사용하지 않는다.

확정 카피:

> 내가 만든 제육볶음과 가장 비슷한 영양정보를 끝까지 찾는 사람.

> 딱 맞는 음식이 없어 오늘도 검색 결과를 추적하고 있습니다. 당신에게 필요한 건 더 긴 검색이 아니라 내 레시피를 바로 기록하는 자동화일지도.

캐릭터와 결과 화면의 구도는 `성분추적러.png`를 유지한다.

### D-06. 나머지 결과 카피

PRD의 전체 문장을 제품 카피로 사용한다. 생성 화면의 짧아진 문장은 시각 배치 참고일 뿐이다.

- 집밥 패스형
  - 강조: `닭가슴살까지는 기록했는데 김치찌개에서 앱을 닫는 타입.`
  - 설명: `기록할 마음은 있었지만 재료가 7개를 넘어가는 순간 인간의 영역이 아니라고 판단합니다.`
- 눈대중 장인
  - 강조: `칼로리는 과학이지만 내 눈도 꽤 정확하다고 믿는 편.`
  - 설명: `비슷한 메뉴를 찾아 빠르게 기록하는 실용주의자. 문제는… 오늘 제육볶음이 검색한 제육볶음과 같다는 보장은 없다.`
- 프로 계량러
  - 강조: `완성 음식까지 저울에 올렸다면 당신은 이미 상위 기록러.`
  - 설명: `재료 무게 ✔ 완성 무게 ✔ 먹은 무게 ✔ 문제는 이걸 매번 계산하는 데 시간이 너무 든다는 것.`

공통 결과 CTA:

- 보조: `내 결과 공유하기`
- 전환 문구: `그런데 집밥 기록이 20초 만에 끝난다면?`
- 주 CTA: `무먹으로 20초 체험하기 →`

### D-07. 결과 공유

- 지원 환경에서는 `navigator.share`로 유형명과 현재 결과 URL을 공유한다.
- 지원하지 않거나 사용자가 취소하면 오류 화면으로 보내지 않는다.
- 지원하지 않는 환경에서는 링크 복사로 대체하고 `링크를 복사했어요.`를 짧게 알린다.
- 공유용 `1200×630` OG 이미지를 로컬 자산으로 제공하고 `og:*`, Twitter Card 메타 태그를 설정한다.
- KakaoTalk 등 외부 서비스의 실제 카드 렌더링은 공개 HTTPS 배포와 크롤러 접근이 있어야 확인할 수 있다. localhost에서는 URL만 보일 수 있다.

### D-08. `20초`의 범위

`20초 체험`은 결과 CTA를 누른 시점부터 제육볶음이 첫 주간 식단에 들어간 시점까지를 뜻한다. 완제품 추가와 베타 신청 시간은 포함하지 않는다.

- 자동 애니메이션 한 번은 0.8초를 넘지 않는다.
- 사용자가 내용을 읽는 시간은 보장 시간에 포함하지 않는 마케팅 표현으로 취급한다.
- 사용자 테스트에서 반복적으로 30초를 넘으면 공개 카피를 `약 20초 체험`으로 조정한다.

### D-09. 체험 데이터 잠금

| 상태 | 값 |
|---|---|
| 돼지고기 | `600g → 520g` |
| 예상·실제 완성 무게 | `1,200g → 1,180g` |
| 먹은 양 | `320g` |
| 섭취 열량 | `487 kcal` |
| 탄수화물·단백질·지방 | `31g · 39g · 22g` |
| 첫 식단 합계 | `1,120 → 1,607 kcal` |
| 첫 단백질 합계 | `72 → 111g` |
| 완제품 | `더:단백 드링크 초코`, `250ml`, `105 kcal`, `단백질 20g` |
| 두 번째 합계 | `1,607 → 1,712 kcal` |

`와이어프레임3.png`에 보이는 제육볶음 `620 kcal`는 오류이며 사용하지 않는다. 제육볶음 한 끼는 항상 `487 kcal`이다.

### D-10. 식단 Payoff

- `식단에 기록하기 →`를 누르기 전에는 제육볶음이 식단에 없어야 한다.
- 누르면 `제육볶음 320g` 행이 집중 이펙트와 함께 들어오고 열량·탄수화물·단백질·지방이 count-up 된다.
- 이 화면은 실제 무먹의 식사 기록 화면 밀도와 토큰을 따르되, 퍼널을 이탈시키는 하단 탭은 넣지 않는다.
- 완제품 `+ 기록하기` 후 같은 저녁 행에 제품이 집중 이펙트와 함께 추가되고 네 영양 요약이 다시 증가한다.

### D-11. 베타 신청

- 이메일은 전체 퍼널에서 유일한 텍스트 입력이다.
- 빈 값과 명백히 잘못된 이메일은 제출하지 않고 입력창 아래에 오류를 표시한다.
- 유효한 이메일은 메모리 상태에만 저장하고 약 500ms의 처리 상태 뒤 완료 화면으로 이동한다.
- 실제 네트워크 요청, 이메일 발송, 데이터 저장은 없다.
- 중복 클릭은 한 번만 처리한다.
- 완료 화면의 `처음으로 돌아가기`는 모든 상태를 지우고 현재 광고 Hero로 돌아간다.

### D-12. 캐릭터와 브랜드 자산

- 퀴즈 전 Hero에는 공식 무먹 로고·심볼을 사용한다. 베타 신청에는 가로 로고와 사용자의 결과 캐릭터를 한 번씩 사용한다.
- 신청 완료에는 환영 포즈로 새로 만든 `public/assets/funnel/characters/welcome-mascot-v2.png`를 사용한다.

- 루트의 캐릭터 원본은 덮어쓰지 않는다. 구현용 PNG는 원본의 얼굴·포즈·소품·흰 외곽선을 유지하고 배경만 제거한 실제 알파 투명 파생본이다.

- 완제품 카드에는 제휴로 오해하지 않도록 `제품 예시`를 작게 표시한다.

- 진행 단계와 자동 변경 메시지는 스크린리더가 알 수 있어야 한다.
- 키보드 포커스가 보이고 논리적인 순서로 이동해야 한다.
- 색만으로 선택·성공·오류를 구분하지 않는다.
- `prefers-reduced-motion`에서는 이동·count-up을 즉시 완료 상태로 보여준다.
- 자동 이동 전에 선택 상태를 확인할 수 있는 최소 시간을 둔다.
- 하단 CTA와 공유 행동은 홈 인디케이터 및 작은 화면에 가리지 않아야 한다.
