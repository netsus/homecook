# Homecook TypeScript evidence review

현재 저장소의 `AGENTS.md`가 범위와 검증 강도를 결정한다. 이 스킬은 변경한 TypeScript/JavaScript를 검토하는 보조 기준이며 제품 계약이나 기존 테스트 관례를 덮어쓰지 않는다.

## 1. 먼저 근거를 고정한다

1. 호출 지점, 입력 경계, 런타임 버전, 관련 타입과 테스트를 읽는다.
2. 확인하지 못한 타입·성능·호환성 가정을 적는다.
3. 요청한 동작에 필요한 가장 작은 변경과 성공 조건을 정한다.

## 2. 변경한 줄만 검토한다

- 한 번만 쓰는 추상화, 미래 요구를 위한 옵션, 기존 스타일과 다른 새 계층을 만들지 않는다.
- `unknown`, 넓은 `object`, 과도하게 일반화한 제네릭을 이미 아는 내부 계약에 사용하지 않는다. 반대로 외부 입력 경계의 `unknown`을 근거 없이 구체 타입으로 바꾸지 않는다.
- 연속 타입 단언, 먼저 넓힌 뒤 다시 좁히는 단언, 검증 없는 `as`로 오류를 숨기지 않는다. 불가피한 단언은 어떤 런타임 검사나 라이브러리 계약이 안전을 보장하는지 가까운 주석 또는 테스트로 남긴다.
- 반복문 안에서 누산기를 매번 펼치거나 복사하는 코드는 입력 크기와 실제 경로를 확인한다. 의미가 같고 읽기 쉬울 때만 지역 누산이나 단일 순회로 바꾼다.
- `filter().map()` 같은 체인은 그 자체로 실패가 아니다. 알려진 배열에서 중간 할당이 실제 문제가 되고 대상 런타임이 대안을 지원할 때만 바꾼다. 희소 배열, 콜백 순서, 인덱스 의미를 보존한다.
- `typeof`는 존재 확인, 타입 가드, 신뢰하지 않는 입력 경계에서 허용한다. 같은 런타임 모양 검사를 여러 호출 지점에 흩뿌리는 경우에만 경계 검증이나 명시적 타입 가드로 모은다.
- 모듈 mocking은 집중된 테스트 경계에서 허용한다. 테스트가 실제 계약을 가리거나 구현 세부사항에만 결합될 때만 더 작은 주입 지점이나 실제 구현 테스트를 검토한다.
- 인접 파일의 기존 문제는 별도 항목으로 보고하고 이번 요청의 근거 없이 함께 고치지 않는다.

## 3. 증거로 닫는다

1. 변경 동작을 직접 재현하는 가장 작은 테스트를 실행한다.
2. 타입을 바꿨다면 관련 `typecheck`, lint 규칙을 바꿨다면 관련 lint를 실행한다.
3. diff를 다시 읽고 모든 변경 줄이 요청 또는 그 검증으로 설명되는지 확인한다.
4. 자동으로 강제된 항목과 리뷰로만 확인한 항목을 구분해 보고한다.
